# 103 + 309 重写骨架

本目录是新程序架构的落地骨架，当前不接入 Keil 工程，不改变现有固件行为。

目标是先固定模块边界，再逐步把旧工程中已经验证过的驱动、协议和参数迁移进来。迁移过程中必须遵守根目录 `REWRITE_ARCHITECTURE_PLAN.md` 中的地址、量产隔离、测试和烧录规则。

## 目录

```text
app/        新主循环调度入口
core/       SOC、低功耗、保护、控制等纯业务状态机
include/    公共模型和数据结构
protocol/   RS485/CAN 寄存器兼容定义
storage/    Flash 分区和持久化边界
```

## 当前状态

- 已定义 `BmsConfig`、`BmsSample`、`BmsState`、`BmsSnapshot` 这组核心模型。
- 已放入简化 SOC 和低功耗状态机的第一版接口。
- 已固化 App/IAP/参数区地址常量。
- 尚未接入 SH367309、RS485、CAN、Flash 写入、LED、MOS 实际驱动。

## 接入原则

1. 驱动层只读写硬件，不做业务仲裁。
2. 保护层只输出故障和允许位，不直接控制 MOS。
3. 控制层是 MOS、加热、均衡的唯一硬件动作出口。
4. 低功耗只有一个请求、仲裁、提交链路。
5. SOC 只读采样和配置，只输出 SOC 状态，不直接写通信寄存器。
