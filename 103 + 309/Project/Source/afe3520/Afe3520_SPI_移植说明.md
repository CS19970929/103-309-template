# SH3673520 配置、IO 与 SPI 说明

本次基线：`codex/afe-spi-refactor-debug`，提交 `78b4f5f` 中的 `InitAFE3520_Registers`。当前工程目标是 STM32F103C8，底层沿用工程 STM32F1 标准外设库。

## Keil 工程接入

打开 `Project/Users/BMS_SH3673520.uvprojx`。FD_Release、FD_Debug 均有 `SH3673520` 分组，直接编译 `Afe3520.c`（SPI/寄存器/采样）、`Afe3520App.c`（应用采样与电流标定接口）、`BmsProtection3520.c`（保护/MOS）、`BmsParameters.c`（持久化软件参数）、`rtc_sleep_afe3520.c`（低功耗接入）；配置头也显示在分组内。

旧 `I2C_AFE1`、`SH367309_Func`、`SH367309_DataDeal` 文件及 `#include .c` 编译占位方式已移除。没有保留 309 寄存器镜像、MTP 读写入口、I²C 地址、旧 AFE 类型选择、未用 ShortFunc/BQ 分支和只写不读的配置标志。驱动初始化、采样、低功耗及 MOS 调用均使用 3520 接口。

软件参数使用 `BMS_PARAMETERS`、`g_bmsParameters` 和 `BMS_SW_*` 命名，替代暗示 AFE ROM/309 硬件的旧内部名称。0x2400 的 24 个寄存器顺序、默认数值、EEPROM 布局及电流 K/B 标定含义保持不变；未启用的其它板型电流配置已删除。参考分支使用连续电芯通道，旧 309 的 13 串跳过 VC9 规则已移除。

工程目录 `103 + 309` 及历史构建记录保留原有位置；它们不是当前芯片选择项。日常构建脚本已指向新工程文件，旧工程文件已删除。本次不修改用户既有调试缓存和历史产物。

## 配置入口

AFE 硬件配置集中在 `Afe3520Config.h`，支持 Keil Configuration Wizard。修改后重新编译。`AFE3520_CFG_WDT_ENABLE` 默认 `0`，改为 `1` 开启 AFE 看门狗；也可以通过编译宏覆盖。启用后，MCU 被调试器暂停并不会冻结外部 AFE 的看门狗。

表中寄存器值为十六进制。电压用 mV 修改；延时、电流、温度原始编码均在配置入口旁说明。温度对应的摄氏温度取决于板上 NTC 曲线，不能只凭阻值换成通用温度。

**KEEP 表示参考分支初始化没有写此寄存器，本工程也不写。** 可以改成 0x00～0xFF 显式配置。KEEP 不代表零，也不保证芯片默认值：若先前固件写过，单独复位 MCU 可能继续保留旧值。首次比较应使 AFE 完整掉电重新上电；本次没有新增强制复位或猜测这些寄存器的默认保护阈值。尤其 OCD1、SC 不能仅依据此配置表得出实际阈值，应读取芯片确认。

MCU 软件保护继续使用现有 `0x2400` 参数区及既有算法，协议含义不变；这些参数不再反向覆盖 AFE 硬件配置。例如软件单体过压阈值仍可能为 3750 mV，达到软件条件仍会报过压，即使尚未达到 AFE 的 4250 mV。排查时应区分 AFE FLAG 与软件故障来源。

## 故障修复与通信评估

- 原采样函数成功返回 1，而 MonitorAFE 将非零当失败，会在正常通信时反复报 AFE1；现统一为成功 0、失败 1。
- 原启动过程通过旧 SH367309 地址别名写配置，实际可能写到 SH3673520 的模式命令寄存器；现经统一 MOS 请求处理。
- MOS 命令每轮重新落实，避免配置恢复关闭 MOS 后被旧缓存跳过；实际状态读取 BSTATUS1，充电还结合 PB14 输出状态，不把软件命令直接当硬件状态。
- FLAG2.bit3 按参考解释为 RST2，触发一次配置恢复，不再误判为断线故障。清保护标志逐寄存器重新授权 LTCLR，并保留无关标志位。
- 默认关闭 WDT，SCONF5 从原 3E 改为参考 18，SCONF2 不开启原 PUMP 配置。采样换算继续采用参考的 `raw × 5 / 32` mV。

## 软／硬 SPI 切换

在 `Afe3520Config.h` 修改下列宏，重新编译同一个 Keil 工程即可：

| 宏 | 默认值 | 用途 |
| --- | --- | --- |
| AFE3520_CFG_USE_HARDWARE_SPI | 1 | 1=STM32 SPI1，0=参考软件 SPI |
| AFE3520_CFG_SPI_TARGET_HZ | 500000 | SCK 上限；硬件自动选择 2～256 分频，软件控制最小半周期 |
| AFE3520_CFG_SPI_TIMEOUT_US | 1000 | TXE/RXNE/BSY 单次等待时限，单位 μs；可配 1～5000 |
| AFE3520_CFG_COMM_RECOVERY_TICKS | 3 | 通信故障后连续正常保护服务周期数；正常调度为 200 ms/周期 |
| AFE3520_CFG_WDT_ENABLE | 0 | AFE 看门狗关闭；改为 1 开启 |

硬件 SPI 依据工程 `STM32F10x_StdPeriph_Lib_V3.5.0/src/stm32f10x_spi.c` 和对应头文件实现：`SPI_StructInit`、`SPI_Init`、`SPI_NSSInternalSoftwareConfig`、`SPI_Cmd`、`SPI_I2S_SendData/ReceiveData/GetFlagStatus`。目标为 STM32F103C8，不使用 F0/HAL 接口。SPI1 不重映射，PA5/PA7 为复用推挽，PA6 浮空输入，PA4 GPIO 控制 CS；全双工、8 位、Mode 3、MSB first、软件 NSS 且内部 NSS 置高。CRC 继续使用 AFE 协议的软件 CRC8，不启用 STM32 的硬件 CRC。

软件 SPI 保留参考 Mode 3 GPIO 顺序，延时改为 TIM4 计时；两种方式共用帧格式、CRC、回显/ACK 校验和最多 5 次传输尝试。硬件字节先等 TXE，发送后等 RXNE 并读 DR；释放 CS 前等 BSY 清零。所有等待有界，不依赖 SysTick 中断，避免 STOP 恢复或异常外设状态下永久等待。任一步超时后该帧不再继续发送后续字节。

TXE/RXNE/BSY 超时或 OVR/MODF 先终止帧并拉高 CS，再通过标准库 `SPI_I2S_DeInit` 的 APB2 外设复位清状态、重新初始化 SPI1；CRC/回显/ACK 错误也从新帧重试。OVR/MODF 不使用只支持 CRCERR 的 `SPI_I2S_ClearFlag` 清除。重试间保留 1 ms 间隔。这里复位的是 MCU 的 SPI 外设，不是 AFE 或整个 MCU。驱动仅由主循环/低功耗流程调用，不支持在中断中并发访问同一总线。

调试器暂停仍可能打断当前帧，但恢复执行后会完成校验、超时退出和重试。关闭 AFE WDT 只能排除外部看门狗超时原因，不能保证任意暂停位置的当前事务有效。软件实际频率仍受 GPIO 调用、优化和中断影响，只保证延时下限，不保证精确达到目标频率；硬件 SCK 来自 PCLK2，帧间和字节间仍可能被中断拉长。

### 系统时钟自动适配

每个 SPI 帧开始时通过本机 F1 标准库 `RCC_GetClocksFreq` 读取实际 HCLK/PCLK1/PCLK2，不依赖可能过期的 `SystemCoreClock` 变量。硬件选择满足 `PCLK2 <= 目标Hz × 分频` 的最小分频，APB2 变化时重建 SPI1；如果 256 分频仍超目标，则报配置错误并拒绝发送，不静默超频。目标配置范围为 10～500 kHz；并非所有时钟下都能实现范围内的每个目标。

默认目标上限 500 kHz 对应：

| PCLK2 | 自动分频 | 硬件 SCK |
| --- | --- | --- |
| 8 MHz | 16 | 500 kHz |
| 24 MHz | 64 | 375 kHz |
| 48 MHz | 128 | 375 kHz |
| 72 MHz | 256 | 281.25 kHz |

TIM4 由 AFE 驱动独占，禁止其他业务复用。每帧计算 APB1 定时器时钟（APB1 分频时自动考虑定时器 ×2），将计数频率限制到 8 MHz 以内。软件半周期、CS 建立/保持和硬件超时都按该频率计算，并用额外一计数补偿计数相位；采用 64 位中间乘法避免 72 MHz/毫秒超时换算溢出。计数差以 16 位无符号回绕处理；另有按 HCLK 计算的有限循环兜底，TIM4 停止时也不会死循环。

TIM4 仅在帧内使能，帧结束关闭计数器及 APB1 时钟，不增加 STOP 的常开外设。STOP 唤醒恢复时钟后，下一帧重新计算参数。系统改频应在主循环两帧之间完成，不支持在中断中途改变正在传输的时钟；物理晶振与 `HSE_VALUE` 定义也必须一致。这是 SPI 模块的适配，不代表其他使用固定时钟常数的外设自动适配。

## 分流器与电流换算

参考分支 `codex/afe-spi-refactor-debug` 的 `DataDeal.h` 设置为 `CS_Res=2`、`CS_Res_Num=8`，即八只 2 mΩ 并联、等效 **0.25 mΩ**。当前默认已在 `conf/conf.h` 对齐；此前误设为两只并联、等效 1 mΩ，会使相同分流电压对应的电流缩小为四分之一。

参考的板级换算是 `I_mA = signed_CADC × 100 × (并联数 × 1000 / 单只毫欧数) / 29127`，当前已同时用于 AFE 原始诊断和上报适配。此前采用的 `200000/65536` 与该参考系数还相差约 11.1%。适配层保留现有校准/SOC 流程的码值单位，其整数截断误差小于一个旧码值（默认分流器约 37.3 mA），上位机电流单位仍为 0.1 A。正值充电、负值放电不变。

上电载入有效配置时，自动把旧错误组合 `2/2` 迁移为当前默认 `2/8` 并保存；其他分流器设置和校准/SOC 参数保持原值。实际运行阻值来自 `OtherElement.u16Sys_CS_Res` 与 `u16Sys_CS_Res_Num`，诊断和上报共同使用 `g_u32CS_Res_AFE`，默认应为 4000。若板内另存了其他阻值，需要通过原参数接口核对，而不是只看编译宏。启动校零现在每次重新读取 AFE，不再反复把同一缓存当作独立样本。

## 上位机显式休眠

原 `0x06` 功能开启命令的功能号 `0x0A` 仅设置普通 `DEEP_MODE`；上位机通信活动、自动空闲调度和开启的 AFE WDT 会清除或阻止该请求，因此点击后可能完全不睡。

现在该命令单独锁存，在每次主循环中处理。等待当前串口/CAN 应答、存储事务及升级结束后保存 SOC 状态，复用保底关断路径，有限尝试关闭 MOS、AFE WDT、均衡和 AFE 采样，然后进入 MCU STOP。指令不会被自动休眠、充放电电流或 AFE 无应答清除；默认新按键边沿唤醒，使用 `AFE3520_CFG_EMERGENCY_CHARGER_WAKE` 控制是否允许 PA0。普通自动休眠规则保持不变。若一直处于升级或存储忙，显式请求保持等待。

## BMS 异常恢复与休眠整改

| 场景 | 当前处理 |
| --- | --- |
| 单次 CRC/回显/ACK/硬件外设异常 | 终止当前帧，恢复 SPI，有限重试；完整校验通过才接受 |
| 5 次仍失败 | 采样无效、配置待核验，置 AFE1/通信/配置故障；PB14 立即低，尝试发送两路 MOS 关闭命令；主循环继续处理通信和恢复 |
| 通信重新可用 | 重新写入显式配置并回读，再取得有效采样；连续正常保护周期达到配置值后解除通信阻止，仍服从温度、电压、电流和系统阻止条件 |
| 配置重写或复位恢复 | 确认均衡关闭，只清 RST1/RST2；不再无条件清 OV/UV/过流/短路/WDT 锁存，其他保护须经过安全条件和稳定恢复计数 |
| 采样或后续 MOS 通信失败 | 本周期不继续使用旧采样更新 SOC；上报数值可保留最后一次有效值，但 AFE 状态标为异常 |
| 高温/低温同时发生 | 各自运行过滤及恢复状态，不因短路求值漏跑另一条件；分别上报高温/低温，零温度编码不会被最小值统计跳过 |
| 长期系统故障 | 8 位错误计数饱和在 255，不再溢出回零造成假正常 |
| 普通低压准备深睡 | 必须已有有效 AFE 数据；升级、存储忙、通信忙、充放电及有效唤醒信号不能被低压条件绕过；阻止条件取消已挂起请求 |
| 普通复位进入休眠 | 先取得 MOS 关闭反馈及 AFE 休眠 ACK，然后保存状态、写对应模式标志、复位；任一步失败回到故障恢复，不提交休眠标志 |
| RTC 间歇唤醒 | 恢复时钟、SPI 引脚与 SPI 外设；采样/保护异常退出休眠；GPIO 唤醒事件不会被 RTC 告警覆盖 |
| STOP 入口 | 在中断临界区检查已有唤醒事件和引脚电平，不在 WFI 前清除新到达的唤醒挂起位；时钟恢复后还原原中断屏蔽状态 |

**开启 AFE WDT 时，普通休眠阻止 STOP 和深睡，保持运行调度；下述保底深睡超时后例外。** STOP 期间无法持续通信，当前没有经过硬件验证的睡眠喂狗方案，因此不假定看门狗会自动冻结。默认关闭 WDT 时正常休眠功能可用。MCU IWDG 与 AFE WDT 是两套功能；本次没有启用原先未调用的 MCU `Init_IWDG()`。

**总线完全断开时，软件无法保证 AFE 放电 MOS 实际关闭。** PB14 能关闭外部充电通路；放电侧依赖 AFE 自身保护及硬件设计。`mosFeedbackValid=0` 表示反馈未知，放电状态保留最后确认值，不伪造“已关闭”。在有效读回之前保持通信故障，普通休眠禁止使用旧数据；保底深睡按故障持续时间触发，不把旧电压当作有效低压。若产品要求断通信立即、确定地断开放电，需要独立硬件关断通路或经过板级验证的 AFE WDT 策略。

调试时查看 `Afe3520_GetDiag()`：`timeoutCount`、`spiErrorCount`、`busRecoveryCount`、CRC/ACK/重试次数；`lastError` 是最近操作结果，`lastFault` 保留最近失败原因，不被后续成功的安全关断覆盖。`Bms3520_GetProtectionStatus()` 提供配置有效性、通信恢复计数、阻止条件和 MOS 反馈有效性。

以上结论来自源码分析、主机故障注入和固件编译。尚未测量 PA4～PA7 波形，未验证真实板上的断线、调试暂停、MOS 关断及 STOP 电流；本次没有烧录。

## 极端异常保底深睡

配置集中于 `Afe3520Config.h`，属于高于普通休眠阻止条件的最终保电策略：

| 宏 | 默认值 | 行为 |
| --- | --- | --- |
| AFE3520_CFG_EMERGENCY_FAULT_SECONDS | 300 | AFE 采样无效、配置无效、通信故障、短路、WDT 或芯片内部温度故障连续达到此秒数后深睡；恢复正常则清零 |
| AFE3520_CFG_EMERGENCY_LOW_SECONDS | 60 | 有效最低单体电压持续不高于原临界阈值且充电电流不大于 0.5 A 时深睡；LIFEPO 为 2650 mV，TERNARY 为 2750 mV |
| AFE3520_CFG_FATAL_SLEEP_ENABLE | 1 | HardFault 等异常及未处理向量直接记录保底标志并复位；调试需要保留原异常现场时改为 0 |
| AFE3520_CFG_EMERGENCY_CHARGER_WAKE | 0 | 默认仅 PB5 新下降沿唤醒；设为 1 才允许 PA0 上升沿唤醒，需确认 AFE WDT 不会产生反复唤醒 |

主循环故障超时后先拉低 PB14，有限尝试关闭 MOS、清除 AFE WDT 使能和关闭均衡/进入 AFE 休眠。任一通信失败都不会阻止 MCU 写入 BKP 保底标志 `0x1238` 并复位。此路径不等待通信、升级或存储忙结束，不等待 EEPROM/Flash 状态保存，可能中断当前业务；临界低压优先进入该路径。

复位后在 RTC、AFE、UART/CAN 和业务初始化之前处理保底标志，关闭 RTC 中断和 SysTick，将 PB14、PA15、PB3、PB4 驱动为低，PA4 CS 置高，其余非唤醒 IO 进入模拟输入，MCU 进入低功耗调压器 STOP。默认不做 RTC 周期重试；卡住的输入电平不会阻止睡眠，按键已经按下时需释放后重新按下。标志直到获准的新唤醒边沿才清除，因此备份域保留时的看门狗/掉压重启会再次直接进入 STOP。

MCU STOP 不等于整机零耗电。AFE 完全失联时，不能保证 AFE 看门狗、均衡或放电 MOS 已关闭；已运行的 MCU IWDG 也不能由软件关闭。未开启 MCU IWDG 的情况下，主循环彻底卡死、栈损坏到无法执行异常处理等不在软件超时保证范围内。本实现降低 MCU 和可控外围持续耗电，上板仍需实测各故障状态电流以及按键唤醒。
