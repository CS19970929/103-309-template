## 分区与构建结果

IAP 仍为 `0x08000000..0x080047FF`；App 为 `0x08004800..0x0800DFFF`，最大 **38912 字节（38 KB）**；日志、配置和 SOC 仍使用 `0x0800E000..0x0800FFFF`。未使用芯片标称容量以外的空间，未减少日志容量。

Keil 工程两个目标的 IROM 长度均由错误的 `0xA000` 改成 `0x9800`，生成的 scatter 同步限制加载区和执行区。镜像初始化数据的压缩加载占用也计入边界。保留安全烧录脚本的地址、长度和存储边界检查。

ARMCC 5.06u7，两目标完整重建均为0错误、7条既有未使用代码警告。RAM 汇总9024字节，包含3 KB栈。BIN长度包含压缩后的初始化数据，不能只以 Code 判断 Flash 用量。

Release 的结束地址（不含）为 `0x0800DF94`，Debug 为 `0x0800DF28`，均未触及 E000 日志页。余量依然有限，修改宏、功能或编译设置后必须重新构建并检查；当前结果不代表任意配置都能放下。保留用户工作区的 Release O2 修改；本次工程提交只改启动文件和容量，不提交用户的优化级别变更。

## 精简内容

- 固定的两个 Modbus 串口直接调用解析函数，删除不存在第二种实现的协议函数指针表、空包装，以及只写不读的发送状态镜像。保留接收/发送中断顺序、错误计数、帧完成交接、TC 后升级标志处理。
- 旧保护区65个字的限值按13组保存，每组四个阈值/恢复字共享上下限，第五字使用延时范围。默认参数、协议索引、允许范围不变；Flash加载与上位机写入共用同一个范围校验入口。新软件 `0x2400`、硬件 `0x2500` 参数仍可读写。
- CRC-16/MODBUS 与存储复用实现；日志和配置/SOC共用 Flash 空白检查；合并双槽保存中重复的最新有效记录选择分支。保留 CRC、序列、回读、失败返回与双槽写入顺序。
- ADC NTC表的温度为固定5℃步进，只保存 ADC 值和明确的温度起点/步进，删除重复温度列和已无调用的通用插值函数。结果仍是 `(℃+40)×10`，端点饱和和整数截断相同。
- AFE充、放电 NTC配置复用成对限值/滞回校验，所有接受和拒绝条件保持。
- ADC1、SPI1、USART1/2使用官方 SPL 对应分支的 RCC 复位调用；ADC DMA1_Channel1按官方 `DMA_DeInit` 的相同寄存器顺序复位，省去其他通道分派。依据为本仓库 `STM32F10x_StdPeriph_Lib_V3.5.0/src`，保留SPI故障后的完整复位及重新初始化。
- 启动表改为 F103C8 的中容量59项（内核16项、外部 IRQ 0..42），删除17个大容量芯片专属向量。与官方 `STM32F10X_MD` 枚举一致，实际中断位置、Reset路径、栈和默认异常处理不变。
- 低功耗删除只写不读的调试状态镜像、刷新函数、未调用的取值接口和无用 LED 阻止宏。保留上位机命令休眠、普通及 RTC周期休眠、低压深睡、异常超时保电、硬故障保底及唤醒恢复；不删除仍占用对外协议地址的旧参数。
