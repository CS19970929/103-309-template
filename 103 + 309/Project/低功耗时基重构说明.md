# 低功耗时基重构说明

## 目标

本次重构把项目时基收敛为一个 BMS 任务调度基准，减少无意义快中断对 Sleep 的唤醒，同时保留现有保护、采样、SOC、通信、显示和低功耗功能。

## 时基架构

### 保留的时基

| 时基 | 来源 | 用途 |
| --- | --- | --- |
| 10ms | TIM3 中断 | BMS 主任务统一调度基准 |
| 50ms | 10ms 软件分频 | 轻量慢任务 |
| 100ms | 10ms 软件分频 | LED 内容刷新等 |
| 200ms | 10ms 软件分频 | AFE 数据、CAN、SOC 等慢任务 |
| 1000ms | 10ms 软件分频 | 低功耗判断、日志、均衡、加热等秒级任务 |
| 1ms LED 扫描 | TIM4 中断 | 仅显示点亮时动态扫描，进入睡眠时关闭 |

### 删除和合并的时基

- 删除 `App_SysTime()` 主循环派生逻辑。
- 删除 `b1Sys1msFlag` 对 BMS 任务的影响。
- 合并 `b1Sys10msFlag1~5` 为 `b1Sys10msFlag`。
- 合并 `b1Sys200msFlag1~5` 为 `b1Sys200msFlag`。
- 合并 `b1Sys1000msFlag1~3` 为 `b1Sys1000msFlag`。
- 删除 `gu8_200msAccClock_Flag`、`gu8_1000msAccClock_Flag` 这类并行全局节拍，SOC 和低功耗直接使用统一的 `SYS_TIME` 标志。

## 调度方式

TIM3 现在按 10ms 进入一次中断，只负责置位待处理标志。主循环开头调用 `SysTime_LatchTaskFlags()`，把中断侧待处理标志锁存到本轮任务快照 `g_st_SysTimeFlag`，然后业务模块读取该快照。

主循环空闲判断改为只查看中断侧待处理标志 `SysTime_HasPendingTaskFlags()` 和串口忙状态。这样本轮已经处理过的 `g_st_SysTimeFlag` 不会阻止 `__WFI()`，主循环可以在任务间进入 Sleep。

## 低功耗策略

- Sleep：主循环无待处理任务、串口空闲且允许 Sleep 时执行 `__WFI()`。
- Stop：进入 Stop 前关闭 ADC/TIM2/DMA，并调用 `LedBar_SetSleep(1u)` 关闭显示扫描。
- Stop：进入 `PWR_EnterSTOPMode()` 前关闭 TIM3，避免系统调度定时器产生待处理中断导致 Stop 驻留失败。
- Stop 唤醒后：`cpu_frequency_conf()` 使用 `SystemInit()`、`SystemCoreClockUpdate()`、`InitDelay()` 恢复到工程统一时钟配置，避免额外切到未统一管理的 PLL 配置。

## LED 扫描边界

LED 动态扫描仍需要较快节拍，否则显示会变慢或闪烁。因此 LED 扫描从 BMS 任务时基中拆出，单独使用 TIM4：

- 显示唤醒时开启 TIM4 1ms 扫描。
- `LedBar_SetSleep(1u)` 时关闭 TIM4 中断并关闭 TIM4 外设时钟。
- TIM4 只服务显示，不再驱动 BMS 保护、采样、SOC 或通信任务。

## 兼容性说明

保护板 BMS 任务原本依赖的 10ms、200ms、1000ms 周期仍保留，只是不再人为拆成多个相位标志。功能周期不变，任务触发入口更集中。原来的 1ms 主调度被移除，ADC 处理改为 10ms，TIM2 触发 ADC 固定为 100Hz，与 10ms 主调度对齐。

后续如果需要进一步降低运行态功耗，可以继续评估：显示亮屏时长、LED 扫描频率、ADC 采样频率、通信唤醒源和 Stop 模式驻留时间。
