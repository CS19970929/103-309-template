# 05 — 保护逻辑说明

## 保护体系概览

BMS 保护采用 **AFE 硬件保护 + MCU 软件保护** 双层架构：

| 保护层级 | 执行者 | 响应速度 | 可配置性 |
|---------|--------|---------|---------|
| AFE 硬件保护 | SH367309 芯片内部 | μs 级（硬件立即响应） | 通过 MTP 寄存器配置 |
| MCU 软件保护 (SW) | STM32 固件 (`DataDeal.c`) | 200ms 级（主循环轮询） | 通过 RS485 可变参数 |
| MCU 熔丝保护 | STM32 GPIO (`PA7`) | 秒级（多次确认后触发） | 硬编码阈值 |

## 三级故障体系

**源文件**: `Fault.h:4-46`

| 级别 | 枚举后缀 | 行为 | 故障标志位置 |
|------|---------|------|------------|
| 一级 (First) | `_First` | 警告，记录但不动作 | `Fault_Flag_Fisrt` |
| 二级 (Second) | `_Second` | 限功率或降电流 | `Fault_Flag_Second` |
| 三级 (Third) | `_Third` | **立即关断 MOS** + 阻止休眠 | `Fault_Flag_Third` + `unMdlFault_Third` |

## AFE → MCU 故障转换

**源文件**: `SH367309_Func.c:240-317` (`Fault_ChangeToMCU()`)

### 转换映射表

```
AFE 寄存器                    →  MCU 故障标志 (unMdlFault_Third)
─────────────────────────────────────────────────────────────
BSTATUS1.OV                  →  b1CellOvp
BSTATUS1.UV                  →  b1CellUvp
BSTATUS1.OCD1 | OCD2         →  b1IdischgOcp
BSTATUS1.OCC                 →  b1IchgOcp
BSTATUS1.SC                  →  System_ErrFlag.u8ErrFlag_CBC_DSG (短路)
BSTATUS2.UTC                 →  b1CellChgUtp
BSTATUS2.OTC                 →  b1CellChgOtp
BSTATUS2.UTD                 →  b1CellDischgUtp
BSTATUS2.OTD                 →  b1CellDischgOtp
```

### 故障边沿记录

**源文件**: `SH367309_Func.c:224-238` (`SH367309_RecordFaultOnActive()`)

使用静态 latch 变量跟踪故障的上升/下降沿：
- **上升沿 (0→1)**: 调用 `FaultWarnRecord2(FaultFlag)` 记录到循环缓冲区
- **下降沿 (1→0)**: 清除 latch（但不记录恢复事件）

### 故障记录缓冲区

**源文件**: `Fault.c:35-42` (`FaultWarnRecord2()`)

```c
// 循环缓冲区 (容量 10)
UINT16 Fault_record_Third2[10];
UINT8  FaultPoint_Third2;  // 环形写入指针
```

- 每次故障触发写入一条记录（故障枚举值）
- 缓冲区满时**覆写最旧记录**
- 可通过 RS485 读取（`Fault_record_Third` 区）

## MCU 软件保护逻辑

**源文件**: `DataDeal.c:1052-1190` (`new_todo_logi()`)

这是 MCU 端独立的软件保护状态机，**不依赖 AFE 硬件检测**。

### MOS 过温保护 (SW)

```
检测频率: 200ms
温度传感器: ADC_TEMP_MOS1 (PB1)
阈值: 关闭 = 95°C, 恢复 = 75°C
动作: close_ctlc() → GPIO_AFE_CTLC = 0 (关闭全部 MOS)
故障记录: MosOTp_Third
```

### 单体过压 + 充电过温 综合保护 (SW, _UL_RENZHENG_ENABLE_)

```
条件: #ifdef _UL_RENZHENG_ENABLE_ (认证模式)
检测电压: CellMax ≥ 4270mV
检测温度: 充电过温 (≥80°C)
AFE 通信故障计数: PEC_ERR_CNT ≥ 2
确认时间: 5 秒持续满足才触发
动作: GPIO_RF_EN = 1 (硬件熔断保险丝)
      + close_ctlc()
```

### SW 独立 OVP/OTP

```
OVP 条件: CellMax ≥ 4280mV, 持续 150ms
OTP 条件: 温度 ≥ 80°C
动作:     记录 CellOvp_Third / BatOvp_Third / CellChgOTp_Third / CellDsgOTp_Third
          动作: close_ctlc()
```

> **风险点**: SW OVP 阈值 `4280mV` 为硬编码，与实际保护参数 `AFE_Parameters_RS485_Struction.u16VcellOvp.curValue` 无关。即使用户通过 RS485 将 OVP 修改为 3650mV (LiFePO4)，SW OVP 仍在 4280mV 触发。

## 故障对系统行为的影响

### 阻止休眠

**源文件**: `rtc_sleep.c:38` — `LP_BLOCK_FAULT` 检查

```c
if (g_stCellInfoReport.unMdlFault_Third.all != 0) {
    block |= LP_BLOCK_FAULT;  // 任何三级故障 → 禁止进入休眠
}
```

### CAN 故障帧上报

**源文件**: `CanFeidaoFrames.c:126-237`

三级故障标志通过 CAN 周期帧发送：
- `CanFeidao_SendStatus5000ms()`: 每 5s 发送故障状态
- 每个故障位在 CAN 帧中有对应的 bit 位置

### RS485 可读

`Fault_Flag_Fisrt/Second/Third` 三个 union 均映射在 RS485 寄存器地址空间，上位机可随时读取。

### RS485 可清除

**源文件**: `Sci_Upper.c:2036-2038`

三级故障标志可通过 RS485 写命令清零（`Fault_Flag_* = 0`）。

## 保护参数配置

**源文件**: `Fault.h:119-198` (PRT_E2ROM_PARAS), `Fault.h:200-308` (默认值)

### 参数结构

每个故障类型有 5 个参数（共 13 × 5 = 65 个 UINT16）：

| 参数 | 含义 |
|------|------|
| `u16[Type]_First` | 一级保护阈值 |
| `u16[Type]_Second` | 二级保护阈值 |
| `u16[Type]_Third` | 三级保护阈值 |
| `u16[Type]_Rcv` | 恢复阈值 |
| `u16[Type]_Filter` | 滤波时间 (单位: 100ms) |

### 化学体系差异化

阈值根据 `TERNARYLI` / `LIFEPO` 宏分为两套默认值。但 SW OVP 中的硬编码阈值未随化学体系切换。

> **风险**: 化学体系阈值在 4 个不同文件中各自用 `#ifdef TERNARYLI` 维护（`Fault.h`, `SH367309_Func.h`, `SH367309_DataDeal.h`, `DataDeal.h`），修改需同步 4 处。

## 已确认的保护链路

```
SH367309 AFE 硬件
  ├── BSTATUS1/2 寄存器 → I2C 读取
  │     └── Fault_ChangeToMCU() → unMdlFault_Third
  │           ├── LP_BLOCK_FAULT (禁止休眠)
  │           ├── CanFeidaoFrames (CAN 上报)
  │           ├── LogRecord (日志记录)
  │           └── FaultWarnRecord2() (循环缓冲区)
  │
  ├── AFE 内部 MOSFET 控制 (硬件自动)
  │     └── MTP_CONF.CHGMOS/DSGMOS → 硬件关断
  │
  └── SH367309_UpdataAfeConfig() → MTP 寄存器配置阈值

MCU 软件 (DataDeal.c)
  ├── MOS NTC 温度 → SW 过温检测 → close_ctlc()
  ├── CellMax 电压 → SW OVP 检测 → close_ctlc() / GPIO_RF_EN
  └── AFE 通信计数 → PEC 故障 → close_ctlc() / GPIO_RF_EN
```

## 待确认的风险点

1. **OVP 阈值不一致**: SW OVP (4280mV) 与 AFE 配置的 OVP 阈值独立，可能导致保护动作不一致
2. **化学校准同步**: 4 个文件中的化学体系阈值定义需要手动同步
3. **BatOvp/BatUvp**: 确认 MCU SW 端是否有独立的 BatOvp/BatUvp 检测逻辑（`DataDeal.c` 似乎仅在 `new_todo_logi` 中涉及）
4. **VdeltaOvp**: 仅确认 Fault.h 中有定义，需要确认是否有对应的检测逻辑
5. **CellSocUp**: SOC 低保护的实际触发条件待确认
