# SOC 连续 OCV 与 3200mV 空电锚点说明

## 1. 目标

本次调整解决四个现场体验问题：

1. MCU 未进入深度休眠、且静置 OCV 条件持续满足时，SOC 应持续重新读取当前 OCV 目标并校准，不能在一次目标捕获后永久停止。
2. 当前三元锂产品将 `V0` 调整为 3200mV。最低单体持续到达该电压后，SOC 必须在明确的确认时间后快速收敛到 0%，同时避免瞬时压降或冷启动单次采样直接显示 0%。
3. 删除独立的 `empty tail` 末端校准器，避免放电状态下仅凭 3200mV～3400mV 电压区间额外修正 SOC。
4. SOC 渐进到 0% 后，在现有低功耗阻塞条件全部解除时直接进入 RTC HICCUP，不再等待普通空闲计时。

本次不修改 Modbus/CAN 寄存器地址、字段含义、CAN ID、Flash 布局和烧录地址。

## 2. 连续静置 OCV

### 2.1 进入条件

普通运行路径继续沿用以下条件：

- 电流方向为 `SOC_MODE_RELAX`，即净电流绝对值小于 200mA；
- `Vmin < 3700mV`；
- 单体电压位于 2000mV～5000mV；
- 单体最大压差不超过 200mV；
- `Vmin`、`Vmax` 相对静置参考值的变化不超过 30mV；
- 未被大电流 sag hold 阻塞。

RTC HICCUP 周期唤醒复用相同的电压有效性和稳定性判断，并按实际休眠秒数推进计时。

### 2.2 校准节奏

| 参数 | 当前值 | 行为 |
| --- | ---: | --- |
| `PROJECT_CFG_SOC_REST_OCV_SECONDS` | 1800秒 | 连续稳定30分钟后取得校准资格 |
| `PROJECT_CFG_SOC_REST_DOWN_STEP_SECONDS` | 300秒 | 取得资格后每5分钟重新读取一次实时 OCV 目标 |
| `PROJECT_CFG_SOC_CALIBRATION_STEP_PERCENT` | 1% | 每次最多向下修正1% |
| OCV deadband | 3% | 当前SOC仅在高于目标超过3%时下修 |

首次满足30分钟稳定条件时立即执行一次最多1%的下修，之后每5分钟重新根据最新 `Vmin` 查表并继续下修。旧的 `rest_ocv_fired` 一次性锁存逻辑已删除。

连续 OCV 仍只做自动向下修正，不自动上调 SOC，避免负载解除后的电压回弹造成剩余电量上跳。若电流、电压范围、压差或稳定性条件被破坏，资格和步进计时清零；重新稳定后可再次进入连续校准。

## 3. 3200mV 空电锚点

### 3.1 参数与曲线

当前三元锂默认和升级后的 `OtherElement.u16Soc_V_0` 均为 3200mV。

三元锂 OCV 末端调整为：

| 最低单体电压 | OCV SOC |
| ---: | ---: |
| 3400mV | 10% |
| 3300mV | 5% |
| 3200mV | 0% |

独立的 `soc_select_empty_tail_step()`、`soc_apply_empty_tail()`、tail 插值表、tail 计时器及 `PROJECT_CFG_SOC_EMPTY_TAIL_START_OFFSET_MV` 参数已经全部删除。3200mV～3400mV 区间不再因放电 tail 强制靠向 0%～10%；该区间只有安时积分会改变运行 SOC，满足完整静置条件时则由统一的连续 OCV 查表逻辑向下修正。

常规自动 SOC 路径因此只保留安时积分、满电确认和连续静置 OCV。另保留 `Vmin <= V0` 的0%边界状态机，用于满足3200mV归零要求；它不再生成3200mV～3400mV的分段 tail 目标。

### 3.2 连续确认与归零

`PROJECT_CFG_SOC_ZERO_CONFIRM_SECONDS` 默认配置为10秒，`PROJECT_CFG_SOC_ZERO_CONVERGE_STEP_SECONDS` 默认配置为1秒。

满足以下条件时累计空电确认时间：

- 当前不是充电状态；
- 单体电压数据有效；
- `Vmin <= OtherElement.u16Soc_V_0`。

连续满足10秒后开始快速渐进收敛：普通运行每1秒最多下降1%，直到通过连续的1%步进到达0%。禁止自动电压校准从较高SOC直接置0。该逻辑是 OCV 表的 0% 电压边界补充，不再与任何 empty/tail 校准器并行，并且在 `Vmin <= V0` 时不受重载 sag hold 阻塞。

RTC HICCUP 周期唤醒同样每次最多下降1%。即使一次RTC唤醒携带了多个步进周期的累计时间，也不会在一次唤醒处理中跨过多个百分点。

以下情况会立即清零确认时间：

- `Vmin` 回升到 `V0` 以上；
- 进入充电状态；
- 单体电压无效；
- RTC 休眠轮次重新开始。

无有效 SOC 快照的冷启动若 OCV 表查到0%，启动值先保留为1%；第10秒后也只能从1%按一个百分点降到0%，不存在高SOC直跳0。RTC HICCUP 路径按累计休眠秒数执行相同确认，因此普通运行和RTC周期低功耗的0%规则一致。真正的深度休眠不执行校准。

### 3.3 SOC 归零后的 RTC 低功耗

当运行 SOC 已按连续1%步进到达0%，且 `Vmin <= V0` 时，低功耗状态机在一秒调度中直接申请 `HICCUP_MODE`。该快速入口仍位于现有低压深睡判断和 `LP_GetBlockReason()` 之后，因此以下安全边界不变：

- 2800mV 强制深睡和配置低压深睡保持更高优先级；
- 存在充电、超过阈值的放电、通信、按键、Flash、升级、故障或 LED 活动时，不进入 RTC；
- 进入 RTC 后按周期唤醒，并继续调用 `SOC_ApplyRtcRelaxationCompensation()`；只要静置 OCV 条件持续满足，就允许持续向下校准；
- RTC 累计达到原有 `PROJECT_CFG_RTC_IDLE_TO_DEEP_SLEEP_HOURS` 后再进入深度休眠。

## 4. 升级覆盖策略

升级参数策略版本更新为 `0x0715`，并启用一次性的 `PROJECT_CFG_UPGRADE_PARAM_RESET_SOC_CONFIG`：

- 升级后首次启动把 SOC 表选择、容量、初始循环参数、`V100` 和 `V0` 恢复为当前产品默认值；
- 当前三元锂默认 `V0` 为3200mV；
- SOC 运行快照不重置，升级前的剩余电量和累计循环数据继续保留；
- 参数策略版本写入成功后不会在后续每次启动重复覆盖。

## 5. 自动验证

`tools/soc_host_c_test.c` 使用真实的 `SOC.c` 和 `SocEnhance.c`，新增并强化以下场景：

- 普通运行连续 OCV 在首次校准后继续按周期重新校准；
- RTC 静置补偿持续重新读取 OCV 目标；
- 3200mV 第9秒不触发，第10秒只下降1%，之后普通运行每1秒继续下降1%；
- 电压中途恢复会重新开始10秒确认；
- RTC 按休眠秒数确认3200mV条件，且每次周期唤醒最多下降1%；
- 3300mV 放电30秒不再触发 empty tail 修正；
- 无快照冷启动在确认完成前保持1%；
- 0、15、30、1000mA 四种板载自耗配置下使用同一套行为测试。

实板仍需验证：3200mV附近的采样抖动、不同放电电流下的压降、充电插入后的计时清零、RTC周期采样以及升级后读取 `0x231B` 确认为3200。
