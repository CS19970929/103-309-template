# 项目变量梳理

本文按当前业务源码梳理项目变量的存储位置、用途和维护边界。统计范围为：

- 业务源码：`103 + 309/Project/Source`
- 项目配置头文件：`103 + 309/Project/Source/conf`
- 不逐项展开 STM32 标准外设库内部变量。
- 不逐项展开 EasyLogger 第三方库内部变量。
- 不逐项列出函数内临时局部变量。本文所称“变量”指模块级全局变量、文件静态变量、对外 `extern` 变量以及关键结构体字段。

说明：函数局部变量数量大、生命周期短，通常只服务于一段计算流程，不适合作为长期维护文档。调试、上位机协议、Flash 持久化、休眠恢复和保护逻辑真正需要长期对照的是下面这些模块级变量和结构体字段。

## 1. 命名和访问边界

| 命名/限定 | 含义 | 维护建议 |
|---|---|---|
| `g_`、`gu`、`g_u` | 跨模块全局变量，通常在头文件中有 `extern` 声明 | 修改前搜索所有读写点，尤其注意中断、通信回调和 200ms 周期任务 |
| `s_` | 文件内 `static` 状态，只属于当前 `.c` 文件 | 优先保持封装，不要为了临时调试改成全局 |
| `volatile` | 可能被中断或异步路径修改 | 读改写需要关注临界区和任务节拍 |
| `const` 表 | 查表参数或映射表，通常烧进 Flash | 修改会改变保护阈值、SOC 曲线或显示映射，需要上板验证 |
| `_mA`、`_mV`、`_A10`、`_10ms` | 单位后缀，分别表示 mA、mV、A*10、10ms tick | 新增变量必须延续单位后缀，避免协议和显示口径混乱 |
| 文件内非 `static` 且无 `extern` | 历史遗留的模块内全局变量 | 不建议新增同类变量，后续可逐步改成 `static` |
| `g_dbg_watch` | Keil Watch 全项目调试目录根入口 | 仅在 `PROJECT_CFG_DEBUG_WATCH_ENABLE` 打开时导出，量产必须关闭；`FD_Debug` 默认启用，Release 全关 |

## 1.1 Keil Watch 调试观察入口

变量收口后，不把所有重要状态改成裸全局变量。需要在线观察时，通过 `PROJECT_CFG_DEBUG_WATCH_ENABLE` 导出只用于调试的观察指针。

当前统一入口只需要在 Keil Watch 添加：

```c
g_dbg_watch
```

`g_dbg` 保留为 `SystemDebug` 内部快照实体，通过 `g_dbg_watch.system.snapshot` 观察；IRQ 计数通过 `g_dbg_watch.system.irq` 观察。

| 观察入口 | 对应模块状态 | 作用 | 备注 |
|---|---|---|---|
| `g_dbg_watch.runtime.ledbar` | `LedBar.c` 的 `s_ledbar` | 观察数码管显示、扫描、按键和唤醒状态 | 旧单模块 `g_dbg_*` 不再新增 |
| `g_dbg_watch.runtime.can_runtime` | `Can_HDX.c` 的 CAN 周期 runtime | 观察 CAN 低功耗发送、周期调度和状态 | 旧单模块 `g_dbg_*` 不再新增 |
| `g_dbg_watch.system.snapshot` | `SystemDebug.c` 的 `g_dbg` | 观察 IO、CAN、低功耗、SOC、模块心跳等快照 | 不需要单独添加 `g_dbg` |
| `g_dbg_watch.system.irq` | `IrqDebug.c` 的 `g_stIrqDebug` | 观察中断计数、最近中断和阶段计数 | `FD_Debug` 默认打开轻量计数，事件 ring 默认关闭 |

## 15. 维护提醒

- `Project_Config.h`、`conf.h` 中的构建档位、runtime SOC 表、Flash 64K 测试开关会改变部分变量是否实际编译。梳理条件变量时必须看条件编译宏。
- 当前未看到活动的 SOC 注入式测试状态机；`SOC_TestMode_RunSample()` / `SOC_TestMode_ReadStatus()` 是 `#if 0` 空壳，`Sci_Upper.c` 的 `SOC_TEST status padding` 仅保留协议长度。
- `FLASH64K_APP_USE_TEST_ENABLE` 打开时，`s_flash64k_use_test` 会持续写读 Flash 做运行中验证，不应出现在量产 Release。
- `g_u16ADCValFilter`、`g_u32ADCValFilter2` 的类型和位宽已有历史问题注释，不要随意改类型。
- `aaaaaa1` 到 `aaaaaa4`、`aaa11` 是无语义调试变量，后续若继续使用，应改成能表达含义的名称。
- `BMS_LOG_POINT`、`BMS_LOG_RECORD`、`Driver_GPIO`、`u32_ChgCur_mA`、`u32_DsgCur_mA` 等没有对外 `extern`，但也没有 `static`，属于历史遗留的模块全局变量。新增代码不要继续扩大这种模式。
- 上位机寄存器读取的核心运行数据集中在 `g_stCellInfoReport`、`PRT_E2ROMParas`、`OtherElement`、`Heat_Cool_Element`、`AFE_Parameters_RS485_Struction`、`RTC_time`、`ProductionInfor`。
- 休眠和 SOC 恢复涉及 `s_stLowPowerRuntime`、`g_irq_t`、`is_wakeup`、`is_rtc_wakekup`、`s_saved_soc`、`s_u32RtcRestCursorSeconds`，修改时必须同步验证 RTC 唤醒路径。
