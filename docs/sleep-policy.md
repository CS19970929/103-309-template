# 开关与休眠策略

PA9 开关低电平为按下，RUN 持续按住 3 秒请求 NORMAL_MODE；用 10 ms 单调 tick 计算实际时长，重复调用不累计时间。休眠前和恢复 RUN 后重置按键状态，仍按住时等待松手；松开后重新按满 3 秒才接受下一次休眠请求。

NORMAL/HICCUP 的 STOP 周期与 DEEP 复位启动后的等待均使用同一按键确认：持续按住 1 秒才接受唤醒，不足 1 秒继续休眠。PA9 使用双边沿中断，以识别松手。唤醒确认在主流程中有界等待，按既有方式喂狗，期间 ADC 保持关闭；确认后才执行外设恢复。充电器等原有有效唤醒源继续保留。

验证入口 `python tools/test_sleep_policy.py` 使用实际 `SleepDeal.c`、`rtc_sleep.c`，以主机硬件替身覆盖时长、松手后重按、tick 回绕、各休眠模式及充电唤醒；实板按键、电流和 MOS 动作需单独验收。

AFE 成功读取的 UV 状态新触发时，在本轮 SOC 计算后通过 `SOC_RequestSetOnce(0)` 同步清零容量、报告和快照，立即请求 DEEP，不等待秒节拍或原低压定时。RTC 周期和按键/串口候选唤醒也先检查 AFE UV，确认后直接执行保存、休眠日志、备份标志和复位，保持 ADC 关闭。

备份域使用 `0x1238` 表示已经处理过放的 DEEP，沿用 DR2/DR3 互反校验，不增加 Flash 标志页。这种软件休眠复位不计入普通重启次数。按键或充电器唤醒后保留过放已处理状态，允许显示 SOC=0 并充电；同一次保护不会被旧电压定时器重复送回 DEEP。仅新的有效 AFE 读取确认 UV 已恢复后，才允许下一次 UV 再触发。客户关放电 MOS、其他放电保护或单次低电压读数均不作为已确认过放。

连续无充放电、外部通信及按键活动达到 `OtherElement.u16Sleep_TimeNormal` 分钟后自动进入 NORMAL，两个电池化学体系的默认表均为 `10080` 分钟（7天）。`u16Sleep_VNormal` 保留地址和数据含义，不参与条件。保留现有电流有效门限；通信、Flash/升级忙或 AFE 数据异常不作为空闲证据，CAN 自身周期广播不计作外部活动。串口有效帧直接重置起点，CAN 活动沿用接收计数及忙状态检测。

用 RTC 无符号时间差衡量空闲，跨 HICCUP/STOP 累计，不依赖恢复后重新启动的 RUN tick。期限到达时直接切为 NORMAL，拉低 CTLC 并重设唤醒源，ADC 保持关闭；最终有效唤醒后恢复 CTLC 与外设。复位后重新开始空闲计时，不写额外 Flash 周期计数。现有已保存的 `u16Sleep_TimeNormal` 按其实际值生效，不强制改写为默认值。
