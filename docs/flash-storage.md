# 主 BMS Flash 持久化说明

适用：STM32F103CBT6（128 KB Flash，1 KB/页）、`FD_Release` / `FD_Debug`。
主 App 仅使用 `[0x08004800,0x0801C000)`，持久化存储在 `[0x0801E000,0x08020000)`。
IAP mailbox 在 `0x20004FE0`；ST-Link、IAP 只能写 App 分区，升级不能覆盖存储页。

配置开关、每组字段范围、MASK 组合及升级步骤统一见 [主 BMS 配置与升级更新手册](configuration-and-upgrade.md)。本文保留存储格式、事务和恢复细节。

## 存储布局

| 数据 | A 页 | B 页 | 写入策略 |
| --- | --- | --- | --- |
| 配置 | `0x0801E000` | `0x0801E400` | 372 字节配置 + 16 字节头；完整双副本，内容变化才写 |
| SOC 状态 | `0x0801E800` | `0x0801EC00` | 52 字节载荷 + 16 字节头，68 字节记录追加，满页切换 |
| 最近100条日志 | `0x0801F000` | `0x0801F400` | 200 字节检查点 + 每条 6 字节追加 |
| 寿命统计 | `0x0801F800` | `0x0801FC00` | 11 个32位计数 + 故障掩码检查点；每条 8 字节增量 |

`0x0801C000`～`0x0801DFFF` 未用于业务存储；新的首次初始化不擦除这段空间。
各记录使用 magic、sequence、length、CRC16、format、最后写入的 commit=0xA55A。写前检查空白、逐半字写入/回读、页擦除后检查全 FF。新记录完成前保留旧记录；seq 按无符号回绕规则比较。CRC 证明数据未变化，**不替代参数合法性校验**。

## 配置恢复、校验与升级

配置载荷保持 372 字节：AFE 24 个 16 位字、RW 参数（保护65字、Other32字、保留24字、加热制冷24字）、32字节产品序列号槽位（复用原布局占位）和 2 字节待完成标志。现有有效配置不迁移格式、不改变存储地址；没有序列号识别标记时仍按旧占位处理。

- 读取 A/B 时，每页分别校验完整记录和配置参数合法性，再选择最新有效记录；已提交但仍有待完成标志的非法配置不回退执行旧事务。
- 保存统一调用配置合法性检查：保护、Other、加热制冷、电流 K/B 和 AFE 参数均必须处于有效范围。协议入口仍负责请求格式及必要的跨字段约束，错误写入不会被写成有效 Flash 记录。
- 两页全空白且状态、日志也空白时，建立出厂默认配置；已知首次初始化半字写入中断且严格符合默认记录前缀时允许重试。非空但损坏、未知格式或遗留状态不会被自动全盘擦除。
- 启动先完成旧记录中已提交的清空意图和 `0x2319` 循环代次补齐；再应用指定的参数更新；最后将参数应用到运行态。失败会有限重试并停留在不进入正常业务的故障循环，需诊断/修复。

升级不再按 `BMS_SOFTWARE_VERDION_DEFAULT` 字符串自动清空，也不再维护九组独立版本。仅使用 `Project_Config.h` 中两个编译选项：

```c
#define PROJECT_CFG_STORAGE_UPDATE_GENERATION 0
#define PROJECT_CFG_STORAGE_UPDATE_MASK 0
```

`GENERATION=0 / MASK=0` 保留已存数据。需要有意更新时，**两个值都必须非零**，且为每次更新使用不同的代次（1～65534）。掩码（0～255）各 bit：

| 位 | 恢复范围 |
| --- | --- |
| 0 | AFE 默认参数 |
| 1 | 65 字软件保护参数 |
| 2 | SOC 的 5 个 Other 配置字 |
| 3 | Other 的剩余参数 |
| 4 | 充/放电电流 K/B |
| 5 | 加热/制冷 24 字配置 |
| 6 | 清空 SOC 状态快照 |
| 7 | 清空最近100条日志（寿命统计不变） |

例如仅更新 SOC 参数：`GENERATION=1`，`MASK=4`；下一次再更新应使用不同代次。SOC 参数更新不主动清状态，额定容量变更后沿用原比例恢复。需要重建 SOC 才同时设置 bit6。
旧配置内 `rw.reserved[6..14]` 的模块版本不再解释：首次读到旧标签时写入 `reserved[6]` 单代次和 `reserved[7]=0x5355` 识别标记，保留其余内容；通信信息和电流校准不受影响。`reserved[8]=0x534E`、`reserved[9]=0xACB1` 配对标记32字节产品序列号；仅两者匹配时解释原 `reserved_legacy[32]` 槽位。未写过时启动使用编译宏，不为保存默认值额外擦写。`reserved[10..14]` 继续保留；配置载荷仍为372字节，序列号槽位偏移338、待完成标志偏移370，CRC、提交顺序和双页掉电恢复机制不变。序列号写入只修改该槽位和两个标记，保留参数、独立11字节编号、波特率、SOC、日志和寿命统计。
待完成清状态/日志时先提交 `initializing`，执行操作后再清标记；重启必须完成已经提交的事务。旧整体初始化待完成位仅用于恢复原有中断事务，不由新版本选项自动产生。

`rw.reserved[0..5]` 是电流 K/B；`[15]` 是波特率档位，`[16..21]` 为 11 字节编号，`[22]` 为编号标签；`[23]` 是显式循环设置代次。普通参数保存和按组更新均保留通信字段及代次。循环写入命令提交成功后，即使 SOC 快照随后失败，启动会根据代次补齐；重复启动不重复设置。

## SOC、日志和统计

SOC 仍为40字节数据、V2布局，当前仅接受 `u16LearnState=0x5343` 的快照。保存精确剩余容量/额定基准、累计等效循环、未满0.01循环的余量、未完成满充目标和低压参考。手动 `0x1005` 已改为先把精确容量立即设为指定 SOC，成功持久化后才 ACK，不再恢复待执行手动目标（该旧字段统一写 `0xFFFF`）；可信 UV 强制归零后利用原有 DEEP 保存流程提交，不可信/疑似断线不清零。**旧 0x534D 标志及百分比回退已删除**：未识别的历史快照不恢复，按当前规则从60%初始化。两个旧百分比字和反码占位写零；状态载荷仍保留原老化位置8字节为不解释的保留区，以保持52/68字节记录和既有 SOC 地址、轮换安全。当前没有工厂老化业务；加热/制冷配置仍保留。

正常积分在整数 SOC 或完整循环变化时按至少 10 秒的正常保存间隔落盘；重要校准状态变化、上位机立即设置 SOC 及 NORMAL/DEEP 前的保存不受该正常限频限制（休眠前最多重试两次），HICCUP 不强制写。普通保存失败最多每秒重试一次。满充/低压和可信 UV 校准规则见 [SOC](soc.md)。

历史日志维护最近100条，存储实际事件编码与间隔（非绝对时间），清空只影响日志。寿命统计与日志分区独立，记录10类故障的上升沿次数和启动次数；持久化活动故障掩码，持续故障跨复位不会重复累计。统计写失败保留 RAM 快照并限频重试，已成功提交的记录通过 CRC/提交标记恢复。

## 错误处理与验证

`ERROR_EEPROM_STORE` 现在能锁存错误，不再因为一次 Flash 失败就触发 DEEP。Keil 可观察 `Flash.c` 的 `s_flash_error`：`address` / `status` / `stage`，stage 1=擦页失败、2=擦后验证、3=半字编程失败、4=编程回读、5=整记录回读。错误结构只保存在 RAM，不增加额外 Flash 写入。启动失败后保持 AFE 未初始化、不进入正常业务；硬件 MOS 最终安全状态仍需实板确认。

验证入口（Windows MSVC + Keil ARMCC5 环境）：`python -B tools/test_storage.py`、`python -B tools/run_soc_host_c_test.py`、`python -B tools/test_uart_protocols.py`、`python -B tools/test_sleep_policy.py`、`python -B tools/test_protection_refactor.py`、`python -B tools/project_check.py -q`，以及 `tools/check_bms_no_bin.py --target FD_Release` / `FD_Debug`。

主机半字中断测试不是实板掉电、Flash 编程电压、耐久性和 UART/CAN 擦页期间时序的验收；通信工具镜像缓存上界已收紧到 `0x0801C000`；任何真实烧录还必须确认目标 BMS IAP 也独立拒绝越界固件。
