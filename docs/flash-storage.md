# Flash 参数与事件存储

适用主 BMS：STM32F103CBT6，128 KB Flash、1 KB 擦除页。App 保持 `0x08004800`～`0x0801BFFF`，SRAM IAP mailbox 保持 `0x20004FE0`，不扩大 App/IAP 边界。

| 内容 | A 页 | B 页 | 写入方式 |
| --- | --- | --- | --- |
| 配置：AFE 24 字 + RW 145 字 + 清空状态 | `0x0801E000` | `0x0801E400` | 完整配置双副本，改变才写 |
| 状态：SOC + 老化时间 | `0x0801E800` | `0x0801EC00` | 小快照追加，满页轮换 |
| 最近 100 条日志 | `0x0801F000` | `0x0801F400` | 每条 6 字节追加，满页轮换 |
| 客户事件统计 | `0x0801F800` | `0x0801FC00` | 独立保留，禁止参数清空擦除 |

记录头包含 magic、sequence、length、CRC16、格式和提交标记。CRC 覆盖关键头字段及 payload；提交半字最后写，逐次擦写校验。选择完整有效的新记录；sequence 支持回绕。新记录提交前保留旧记录。SOC 和老化分别修改共享快照的对应字段，保留另一方最近已提交内容。

按当前产品要求，不迁移 SOC V1、旧 RW 长度、旧老化标志或旧地址。首次部署本格式需要初始化参数；后续版本均按以下策略处理。

`Project_Config.h` 集中控制升级后的参数更新，IAP 和保留存储区的 ST-Link App 烧录使用相同启动流程。默认 `PROJECT_CFG_RESET_PARAMS_ON_NEW_VERSION=0`，以下各模块版本也为 0：保留有效配置和状态，不因软件版本变化而清空。模块版本取 1～65534 时，仅在落盘版本不同的首次启动更新该组；0 表示保持，65535 保留给尚未设置的存储字。后续更新该组必须换用新的版本号，仅修改默认表或软件版本字符串不会重复覆盖用户参数。空白、无效配置仍初始化默认参数，不读取旧格式。

| `PROJECT_CFG_PARAM_..._VERSION` | 更新范围 |
| --- | --- |
| `AFE` | AFE 24 字配置；仍走既有 AFE 启动应用和回读流程 |
| `PROTECT` | 软件保护 65 字配置 |
| `SOC` | `u16Soc_TableSelect`、`u16Soc_Ah`、`u16Soc_Cycle_times`、`u16Soc_V_100`、`u16Soc_V_0` |
| `OTHER` | Other 的其余字段，排除上述 5 项，协议地址不变 |
| `CALIB` | 持久化的充放电电流 K/B 校准 |
| `HEAT_COOL` | 加热/制冷配置 |
| `SOC_STATE` | 丢弃 SOC/容量/循环等快照，下次 SOC 初始化按原规则重建；保留老化状态 |
| `AGING_STATE` | 丢弃老化状态；保留 SOC 快照 |
| `LOG` | 清空最近 100 条日志，保留寿命事件计数 |

例如只更新 SOC 配置：保持总清空为 0，只将 `PROJECT_CFG_PARAM_SOC_VERSION` 从 0 改为 1（下一次改为 2）；其余版本保持 0。SOC 配置更新不主动清除快照：额定容量改变后按原 SOC 比例（包含可恢复的小数）换算当前容量；`u16Soc_Cycle_times` 的配置初值不会覆盖有效快照内的累计循环数。若确实需要重建快照，再单独调整 `SOC_STATE` 版本。当前 SOC 已精简为纯安时积分，自动电压/OCV/自耗修正均已移除；历史只读电压表仅为协议兼容数据，不参与 SOC 计算。运行和保存规则见 [SOC](soc.md)。

`PROJECT_CFG_RESET_PARAMS_ON_NEW_VERSION=1` 为显式整体初始化，优先于模块选择，仍以 `DataDeal.h` 的完整 `BMS_SOFTWARE_VERDION_DEFAULT` 字符串判断新版本，不使用编译时间；会清参数、SOC/老化状态和日志，始终保留寿命统计。模块版本相同、普通重启和保留存储的重复烧录都不再更新。版本号只表示是否需要执行，不比较大小；回退到不同的非零版本也会执行，不要复用已发布的版本号。

沿用 372 字节配置格式，在 `rw.reserved[6..14]` 保存 9 个模块版本，前 6 字仍为电流校准，普通上位机 RW 参数保存保留这些私有版本。现有同格式记录中的未设置版本（0xFFFF）无需整体重置。配置字段与版本在一次双页提交中生效，不新增 Flash 页、不迁移旧格式。

电池通信设置也沿用同一记录：`rw.reserved[15]` 保存波特率模式 1/2/3（9600/19200/115200）；`[16..21]` 按每字高字节在前保存 11 字节 ASCII 电池编号及末尾 `0xFF`；`[22]` 为编号有效标记 `0x424E`，`[23]` 继续保留。已有有效记录的未设置字段按默认 9600 和 `00000000000` 读取，不重置整组参数。写入走原有配置双副本、CRC、提交标记和回读核验，记录大小、地址和擦写粒度保持不变。普通 RW/校准保存及模块独立更新保留这些字段；显式整体初始化恢复默认值。对应 Modbus 读写和切速时机见 [串口协议](uart-protocols.md)。

跨状态/日志的更新先持久化配置、目标版本和 `initializing` 待完成位，再清对应数据，最后提交 `initializing=0`。位 0 为整体清空，位 1/2/3 为 SOC/老化/日志；掉电后先完成已有意图，即使下一份固件将该模块设为 0，也不能跳过。状态仅追加对应字段无效的新快照，保留另一方数据；日志沿用原清空记录。整体初始化仍擦除 `0x0801C000`～`0x0801F7FF` 中除配置双页外的区域。只有所有操作成功才进入正常 AFE/应用启动，统计两页始终不在清空范围中。备份域 RTC 时间不属于 Flash 参数。

日志单条为 `[event, delta, CRC16, commit16]`，只追加 6 字节。每页头部包含最近 100 条的校验快照与 generation，之后可追加 134 条；仅切页时写一次快照。这样即使连续掉电耗尽多个未完成记录槽，擦除另一页前仍保有全部最近历史。启动只回放最新有效页，内部清空标记只影响日志。上位机仍从 `0xC008` 读取 100 个寄存器，返回 200 字节 `[event, delta]`、最新在前，支持原 20 字分段读取；`0x1007=1` 只清日志。

IAP 与 ST-Link 仅更新 App 时走相同启动初始化。ST-Link 全片擦除会连同内部 Flash 统计一起擦除，软件无法保留；升级必须保留 `0x0801C000` 及其后的存储区。不要把 App 裸写到 `0x08000000`。

统计页头的快照保存 11 个 `UINT32` 计数和最近故障掩码；页内每条 8 字节记录故障掩码变化、重启或清零。仅满页轮换和写失败恢复时写完整统计快照，启动只回放最新页，避免重复累计。计数内部饱和于 `UINT32_MAX`；命令5仅清前 10 项，保留掩码，所以持续故障跨复位或清零不会重复记数。统计全部损坏或存在已提交但校验失败的记录时，报告不可用，禁止自动当作首次使用清零。全空白区域创建初始统计；仅对严格匹配首次初始化写入前缀、且不存在其他数据的中断写入，允许重做首次初始化。

统计在 `Runtime_Boot` 最前面捕获 `RCC->CSR`、备份域睡眠标志，然后清除复位原因并记录本次启动。只有软件复位原因与有效睡眠标志同时匹配、且无 POR/watchdog/低功耗复位原因时，才排除主动休眠复位；残留睡眠标志不能掩盖 watchdog。普通运行在有效 AFE 周期最终 MOS 仲裁后更新故障统计，UART 解析不再修改计数。

写失败保留 RAM 统计与待保存状态，正常循环最多每秒重试一次，休眠前再尝试一次；通过完整快照恢复，避免不确定的增量重复。统计错误不增加 MOS 关断条件。突然断电仍可能丢失尚未成功提交的事件，内部 Flash 无法保证未获得写入时间的事件持久化；已提交记录由双页和提交标记保护。

主机验证入口：`python tools/test_storage.py`。它运行实际 Flash/启动代码，模拟每个擦除/半字写入中断点；不代表实板掉电、低压或擦写寿命验收。

## 板上后台自动自测

`Project_Config.h` 的 `PROJECT_CFG_STORAGE_SELF_TEST_ENABLE` 默认为 `0`。置 `1` 后，上电自动启动；不需要主机持续下发命令，也不需要真实充放电来推进。正式发布关闭该宏，整个自测状态、任务和测试区访问分支均不参与编译。

自测在 `Runtime_RunOnce` 正常业务之后执行，每轮主循环最多推进一个存储动作，不额外等待固定 tick。每个动作结束都返回主循环，先运行正常业务，再判断能否继续自测。通信收发、CAN 工作、待处理节拍、AFE 通信异常、Flash 忙、IAP 或非 RUN 模式期间暂停。期间视为活动，`LP_BLOCK_STORAGE_TEST`（bit 10）阻止自动 HICCUP 和七天空闲 NORMAL；手动 NORMAL、确认过放与原有低压 DEEP 优先。普通 STOP 唤醒继续，MCU 复位从测试区恢复已提交进度。看门狗复位直接报告测试失败。

### 地址与业务隔离

| 内容 | 测试 A/B 页 | 正式 A/B 页 |
| --- | --- | --- |
| 配置与测试进度 | `0x0801C000` / `0x0801C400` | `0x0801E000` / `0x0801E400` |
| SOC 与老化状态 | `0x0801C800` / `0x0801CC00` | `0x0801E800` / `0x0801EC00` |
| 日志 | `0x0801D000` / `0x0801D400` | `0x0801F000` / `0x0801F400` |
| 事件统计 | `0x0801D800` / `0x0801DC00` | `0x0801F800` / `0x0801FC00` |

测试区正好使用原有 App 上限之后、正式存储之前的预留 8 KB；不改变 App `0x08004800..0x0801BFFF`、IAP 或正式数据格式。两套页共用同一组记录提交、校验、合并、回放和轮换函数，统计使用独立运行状态。虚拟 SOC、参数、故障和启动事件只写测试区，不改变实际 SOC、MOS 请求、参数、最近100条日志或客户计数。

首次使用要求测试区为空。遇到未知数据、损坏记录或目标与已保存测试配置不同，报告失败并保留现场，不自动擦除。需要重新测试时，用调试器仅擦除 `0x0801C000..0x0801DFFF` 的八个 1 KB 页后复位；不得全片擦除或擦除正式存储。原有显式整参数初始化会按原规则清除该预留区域；如果该初始化在新版本启动时执行，完成标记也会被清除。App 下载地址仍为 `0x08004800`。

当前测试模式标记为 `TST2`（`0x54535432`），配置阶段新增合法波特率、11字节编号和有效标记的模式验证。旧 `TST1` 进度或完成结果不会直接记为本轮通过，会以 `first_error=5` 停测并保留现场；运行新测试前仅清空上述测试区。正式参数记录的格式版本、大小和地址未改变。

板上自测不会主动断电或反复复位。续测基于完整提交的记录；写入中断留下未完成槽时，自测严格检查并停测保留现场。正常存储的掉电一致性由主机逐擦除/半字写入断点注入覆盖，实际掉电还需实板验收。

| Project_Config.h 参数 | 默认有效提交数 | 含义 |
| --- | ---: | --- |

SOC 每200次与老化状态交替更新并检查另一方未被覆盖；定期重复保存同一份配置/SOC，要求不产生编程操作。日志逐步回读最近100条并检查顺序、清空和切页。统计每步丢弃临时运行状态，重新从Flash回放并比对；主阶段后继续检查17次启动累计、清零保留掩码、持续故障不重复记数、恢复后再次发生才加一。最后重新核对各域，提交完成标记并停止。后续启动先验证已完成数据，通过后直接恢复 PASS，不重跑擦写。

配置每次提交在完整字节模式中轮换波特率模式1/2/3、11位ASCII十进制测试编号、末字低字节 `0xFF` 和有效标记 `0x424E`，均通过原有整包CRC与回读比对。只写测试配置，不调用实际UART切速。主机回归另外验证新接口的默认值、非法值、ASCII边界与字节序、所有模块更新组合及更新中断后保留字段、显式整体初始化恢复默认值，以及自测与正式通信设置交错写入的隔离。

测试是用户存储事件的加速回放，不加速系统 RTC 或真实 SOC 算法，不代表实际积分精度验收。测试 SOC 现有保留字段中含恢复进度用的序号，只存在于测试页。正常参数写入、真实 SOC、日志和客户计数继续使用原公开接口。

默认目标约84.2万个动作。已取消原来每次动作固定等待20 ms的节流，因此不再有约4.7小时的固定间隔下限；实际耗时由Flash擦写、校验和正常业务占用决定，需在板上计时，不能用主机模拟耗时代替。次数和校验内容保持不变。接线与功能检查可先使用配置100、SOC1000、日志3000、统计1000的目标；目标改变后必须先确认并只清空测试区，旧批次不能算作新目标通过。

### 观察结果与失败边界

Keil Watch 添加 `sys_time.flash_test`：

先用启用测试宏的固件与对应AXF进入硬件Debug，点击Run保持运行；通过 `View -> Watch Windows -> Watch 1` 添加上述结构并展开。勾选 `View -> Periodic Window Update`，运行中才会周期刷新（见[Keil Watch说明](https://www.keil.com/support/man/docs/uv4/uv4_db_dbg_watchwin.asp)）。观察时不要反复停核来判断运行时序；看门狗复位会记录错误6。测试宏关闭时该结构不编译，Watch找不到它是正常现象。

- `status`：1 RUNNING、2 PASS、3 FAIL、4 BUDGET_LIMIT；PASS只表示这组目标与回读校验已通过。
- `progress.phase`：0初始化、1配置、2SOC、3日志、4故障统计、5启动累计、6清零、7恢复、8最终检查、9完成。
- `progress.goal[] / count[]`：顺序为配置、SOC、日志、统计；计数仅表示已校验的提交，擦除、老化交替更新和阶段检查点另计实际操作。
- `session_erases[0..7]`：按测试页地址从低到高的本次 `FlashSelfTest_Init` 后实际成功擦除次数；`session_halfwords` 为同期实际成功编程半字数。不包含此前启动参数初始化的擦写。普通 STOP 保留，MCU 复位重新初始化，不冒充芯片全寿命擦写计数。
- `checks`、`resumed`：本次校验次数与从测试区恢复标志。
- `first_error / first_error_address`：首次异常后停止测试，保留原因与地址。错误1擦除、2编程、3读取、4数据比对、5测试配置、6看门狗、7UART ORE、8业务节拍溢出、9擦写预算。

正常观察顺序：`status=1`、`budget_ok=1`、`first_error=0`，配置/SOC/日志/统计的 `count[]` 依次推进。四项达到 `goal[]` 后还会验证启动累计、清零与恢复；必须等到 `status=2 && progress.phase=9 && first_error=0` 才是通过。`status=1` 时计数暂时不变可能在等待正常业务让行，不能直接认定Flash卡死。MCU复位后 `resumed=1` 表示识别了本轮持久进度，`session_*` 重新计数；这些不是芯片全寿命次数。

UART ORE 检查依赖现有 `PROJECT_CFG_IRQ_DEBUG_ENABLE`（当前默认开启）；关闭时只跳过这一项观察。保护、采样和通信仍由正常任务运行。F103擦页期间不能从同一Flash取指，后台分步不等于零延迟；带载SOC计量、保护响应时间、通信丢帧和真实掉电必须实板验收。

启动前保守估算各测试页的擦除预算，目标超出单页10000次规格范围则不写入，报告 BUDGET_LIMIT；本次启动的计数到上限也停止。规格依据为[ST STM32F103x8/xB 数据手册](https://www.st.com/resource/en/datasheet/stm32f103cb.pdf)的 Flash endurance（10 kcycles）；器件温度与保持时间仍按表内条件区分。默认值在此范围内，但不能由 PASS 推导正式两页SOC已满足十年每天完整循环。中途复位之前的失败擦写、器件原有损耗、温度和长期数据保持不由这些计数覆盖，测试会真实消耗测试页寿命。
