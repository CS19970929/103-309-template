# Flash 参数与事件存储

适用主 BMS：STM32F103CBT6，128 KB Flash、1 KB 擦除页。App 保持 `0x08004800`～`0x0801BFFF`，SRAM IAP mailbox 保持 `0x20004FE0`，不扩大 App/IAP 边界。

| 内容 | A 页 | B 页 | 写入方式 |
| --- | --- | --- | --- |
| 配置：AFE 24 字 + RW 145 字 + 清空状态 | `0x0801E000` | `0x0801E400` | 完整配置双副本，改变才写 |
| 状态：SOC + 老化时间 | `0x0801E800` | `0x0801EC00` | 小快照追加，满页轮换 |
| 最近 100 条日志 | `0x0801F000` | `0x0801F400` | 每条 6 字节追加，满页轮换 |
| 客户事件统计 | `0x0801F800` | `0x0801FC00` | 独立保留，禁止参数清空擦除 |

记录头包含 magic、sequence、length、CRC16、格式和提交标记。CRC 覆盖关键头字段及 payload；提交半字最后写，逐次擦写校验。选择完整有效的新记录；sequence 支持回绕。新记录提交前保留旧记录。SOC 和老化分别修改共享快照的对应字段，保留另一方最近已提交内容。

按当前产品要求，不迁移 SOC V1、旧 RW 长度、旧老化标志或旧地址。首次部署本格式需要初始化参数；后续版本均按以下策略处理。

`Project_Config.h` 集中控制升级后的参数更新，IAP 和保留存储区的 ST-Link App 烧录使用相同启动流程。实际值以当前配置为准。`PROJECT_CFG_RESET_PARAMS_ON_NEW_VERSION=0` 且各模块版本为 0 时，保留有效配置和状态，不因软件版本变化而清空。模块版本取 1～65534 时，仅在落盘版本不同的首次启动更新该组；0 表示保持，65535 保留给尚未设置的存储字。后续更新该组必须换用新的版本号，仅修改默认表或软件版本字符串不会重复覆盖用户参数。空白、无效配置仍初始化默认参数，不读取旧格式。

| `PROJECT_CFG_PARAM_..._VERSION` | 更新范围 |
| --- | --- |
| `AFE` | AFE 24 字配置；仍走既有 AFE 启动应用和回读流程 |
| `PROTECT` | 软件保护 65 字配置 |
| `SOC` | `u16Soc_TableSelect`、`u16Soc_Ah`、`u16Soc_Cycle_times`、`u16Soc_V_100`、`u16Soc_V_0` |
| `OTHER` | Other 的其余字段，排除上述 5 项，协议地址不变 |
| `CALIB` | 持久化的充放电电流 K/B 校准 |
| `HEAT_COOL` | 加热/制冷配置 |
| `SOC_STATE` | 丢弃 SOC/容量/循环等快照，下次 SOC 初始化按原规则重建；保留老化状态 |
| `AGING_STATE` | 丢弃老化状态；保留 SOC 快照 |
| `LOG` | 清空最近 100 条日志，保留寿命事件计数 |

例如只更新 SOC 配置：保持总清空为 0，只将 `PROJECT_CFG_PARAM_SOC_VERSION` 从 0 改为 1（下一次改为 2）；其余版本保持 0。SOC 配置更新不主动清除快照：额定容量改变后按原 SOC 比例（包含可恢复的小数）换算当前容量；`u16Soc_Cycle_times` 的配置初值不会覆盖有效快照内的累计循环数。若确实需要重建快照，再单独调整 `SOC_STATE` 版本。当前 SOC 以安时积分为主，按最高单体确认满充目标，只在最低单体不高于3050 mV的实际放电末端平滑纠偏；不做启动/静置OCV或自耗修正，历史只读表仍不参与计算。所有校准限速，不在满充、过放或重启时直接改容量；运行和保存规则见 [SOC](soc.md)。

`PROJECT_CFG_RESET_PARAMS_ON_NEW_VERSION=1` 为显式整体初始化，优先于模块选择，仍以 `DataDeal.h` 的完整 `BMS_SOFTWARE_VERDION_DEFAULT` 字符串判断新版本，不使用编译时间；会清参数、SOC/老化状态和日志，始终保留寿命统计。模块版本相同、普通重启和保留存储的重复烧录都不再更新。版本号只表示是否需要执行，不比较大小；回退到不同的非零版本也会执行，不要复用已发布的版本号。

沿用 372 字节配置格式，在 `rw.reserved[6..14]` 保存 9 个模块版本，前 6 字仍为电流校准，普通上位机 RW 参数保存保留这些私有版本。现有同格式记录中的未设置版本（0xFFFF）无需整体重置。配置字段与版本在一次双页提交中生效，不新增 Flash 页、不迁移旧格式。

电池通信设置也沿用同一记录：`rw.reserved[15]` 保存波特率模式 1/2/3（9600/19200/115200）；`[16..21]` 按每字高字节在前保存 11 字节 ASCII 电池编号及末尾 `0xFF`；`[22]` 为编号有效标记 `0x424E`；`[23]` 现保存显式循环设置的提交代次，旧记录的 `0xFFFF` 表示未启用，不重置旧 SOC。已有有效记录的未设置字段按默认 9600 和 `00000000000` 读取，不重置整组参数。写入走原有配置双副本、CRC、提交标记和回读核验，记录大小、地址和擦写粒度保持不变。普通 RW/校准保存及模块独立更新保留这些字段；显式整体初始化恢复默认值。对应 Modbus 读写和切速时机见 [串口协议](uart-protocols.md)。

显式写 `0x2319`（包括同值重写和恢复 Other 默认）时，配置中的循环值和 `reserved[23]` 代次一次提交；V2 SOC 的 `u16Reserved[0]` 保存已应用代次。配置提交是该命令的持久化生效点，SOC 快照失败时仍可正常 ACK，因为重启会按代次补齐循环值、清放电余量并保留已保存容量；后台也继续重试。未提交的配置写入返回失败且不改运行态。启动先完成代次同步，再应用模块默认参数；恢复失败则不进入正常业务。普通保存保留代次，相同代次不会重复重置已累计循环。代次使用 1～65534，回绕时跳过现存快照代次；记录长度、地址、CRC、格式版本均不变。旧版固件不理解该代次，带新代次设备不应回退到旧 SOC 固件后继续累计。

SOC V2记录大小及版本不变。平滑校准使用原退休字段：`u16LearnState=0x534D`、`u16Reserved[3]=0xACB2`为成对识别标记；退休的`u16MaxErrorPercent`保存满充电压，启动时与当前配置不一致则取消旧上端目标/锁存，覆盖参数已提交但RAM副作用尚未执行时掉电的情况；`u16LearnAnchorSoc`为手动目标0～100或0xFFFF（无目标）；`u16Flags`的bit0/1/2分别为上端目标、上端已确认锁存、过放零目标，其余位必须为0。`u16Reserved[1..2]`低字在前保存低压进入参考容量（0.1 A*s），必须不超过保存的满容量；`[0]`仍只用于循环提交代次。标记/反码、目标、标志组合或容量参考非法时只忽略校准元数据，不丢弃原容量。旧V2快照没有该标记，不解释旧退休字段、不清数据；额定容量变化时低压参考与当前容量一并按比例恢复。

手动0x1005先提交目标与当前容量，成功ACK不表示已到达目标；失败拒绝目标且RAM保持原值。过放事件只记录零目标，睡前保存当前容量，不直接清零；重启不能把目标当作已完成容量。整数SOC/完整循环/校准状态变化触发保存，小数修正不逐周期写。记录仍由原CRC和最终提交标记覆盖，老化/统计及页轮换机制不变。降级到不理解平滑元数据的旧固件会丢弃未完成目标，但不改变记录布局。

跨状态/日志的更新先持久化配置、目标版本和 `initializing` 待完成位，再清对应数据，最后提交 `initializing=0`。位 0 为整体清空，位 1/2/3 为 SOC/老化/日志；掉电后先完成已有意图，即使下一份固件将该模块设为 0，也不能跳过。状态仅追加对应字段无效的新快照，保留另一方数据；日志沿用原清空记录。整体初始化仍擦除 `0x0801C000`～`0x0801F7FF` 中除配置双页外的区域。只有所有操作成功才进入正常 AFE/应用启动，统计两页始终不在清空范围中。备份域 RTC 时间不属于 Flash 参数。

日志单条为 `[event, delta, CRC16, commit16]`，只追加 6 字节。每页头部包含最近 100 条的校验快照与 generation，之后可追加 134 条；仅切页时写一次快照。这样即使连续掉电耗尽多个未完成记录槽，擦除另一页前仍保有全部最近历史。启动只回放最新有效页，内部清空标记只影响日志。上位机仍从 `0xC008` 读取 100 个寄存器，返回 200 字节 `[event, delta]`、最新在前，支持原 20 字分段读取；`0x1007=1` 只清日志。

IAP 与 ST-Link 仅更新 App 时走相同启动初始化。ST-Link 全片擦除会连同内部 Flash 统计一起擦除，软件无法保留；升级必须保留 `0x0801C000` 及其后的存储区。不要把 App 裸写到 `0x08000000`。

统计页头的快照保存 11 个 `UINT32` 计数和最近故障掩码；页内每条 8 字节记录故障掩码变化、重启或清零。仅满页轮换和写失败恢复时写完整统计快照，启动只回放最新页，避免重复累计。计数内部饱和于 `UINT32_MAX`；命令5仅清前 10 项，保留掩码，所以持续故障跨复位或清零不会重复记数。统计全部损坏或存在已提交但校验失败的记录时，报告不可用，禁止自动当作首次使用清零。全空白区域创建初始统计；仅对严格匹配首次初始化写入前缀、且不存在其他数据的中断写入，允许重做首次初始化。

统计在 `Runtime_Boot` 最前面捕获 `RCC->CSR`、备份域睡眠标志，然后清除复位原因并记录本次启动。只有软件复位原因与有效睡眠标志同时匹配、且无 POR/watchdog/低功耗复位原因时，才排除主动休眠复位；残留睡眠标志不能掩盖 watchdog。普通运行在有效 AFE 周期最终 MOS 仲裁后更新故障统计，UART 解析不再修改计数。

写失败保留 RAM 统计与待保存状态，正常循环最多每秒重试一次，休眠前再尝试一次；通过完整快照恢复，避免不确定的增量重复。统计错误不增加 MOS 关断条件。突然断电仍可能丢失尚未成功提交的事件，内部 Flash 无法保证未获得写入时间的事件持久化；已提交记录由双页和提交标记保护。

主机验证入口：`python tools/test_storage.py`。它运行实际 Flash/启动代码，模拟每个擦除/半字写入中断点；不代表实板掉电、低压或擦写寿命验收。

## 自测移除后的边界

板上 `FlashSelfTest_*` 压力自测及其测试开关、后台任务和休眠阻塞已移除。`0x0801C000`～`0x0801DFFF` 继续保留，不扩大 App 链接范围、不作为新的业务存储区。参数整体初始化仍沿用原擦除范围；正式配置、状态、日志、统计的页地址、布局、CRC、提交标记、切页和掉电恢复均不变。

SOC 共享状态中的历史老化字段及配置中的加热字段继续保留布局。固件不再导出无调用的老化读写包装；host 存储测试通过真实状态日志验证这些保留字节在 SOC 保存和复位中的完整性。验证入口仍为 `python -B tools/test_storage.py`，不执行实板擦写。
