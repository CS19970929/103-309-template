# SOC 与 SH367309 单体采样可信性（2026-11-16）

主工程：`103 + 309/Project`，核心文件 `SOC.c`、`I2C_AFE1.c`、`DataDeal.c`、`SleepDeal.c`、`rtc_sleep_afe_sh367309.c`。仅适用当前 5～16 串配置。**电池保护动作优先于 SOC 校准，校准不得让 MOS 放行。**

## 一、AFE CELL 解码与采样故障

- SH367309 CELL 为有符号 16 位原始码；按字节序调整后以 `int16_t` 解释，单位 mV 的换算为 `raw*5/32`。原先把负码当 `uint32_t`，会把 `0xE000`/`0xF000`/`0xFA00` 错显为约 8960/9600/10000 mV。
- 每轮先验证全部物理串的映射与电压 `0 < mV <= 5000`，只在全部通过后统一发布。返回码：`0` 有效、`1` I²C 失败、`2` 两个实际 NTC 异常、`3` 单体数据/映射异常。13 串索引重复 9 已修成 8、9；物理采样顺序必须核对实板。
- 连续采样中，相邻两节各自反向变化至少 800 mV、两节变化总和在 ±200 mV 内，则判为断线**疑似**，不提交该帧。此为保守异常特征，不等同物理断线证明；断线也可能产生两个仍然貌似正常的数值。
- PF 可能伴随采样冻结；有 PF 时不使用该帧做 SOC 积分、100%/0% 校准，不开放 CTL。PF 亦可能与二次保护共用，不能仅凭 PF 无歧义地判断哪根线断开。需实板确认 `SCONF2.DIS_PF` 配置及真实行为；本轮不修改 AFE EEPROM 断线检测开关。
- 原始值应保留可调试证据；冻结的旧电压不能当成新证据。异常采样不得解除既有 UV、MOS 或其他保护。

## 二、容量与积分

- `SOC.c` 只维护一份容量 `now_as10`，额定基准 `full_as10`；单位均为 0.1 A·s。200 ms 的有符号 mA 积分有 mA·ms 余数，正=充电、负=放电；无有效电流时不补积分。
- 整数 SOC 按 `now_as10/full_as10` 四舍五入，0～100%。SOH 仍是既有循环次数估算，未引入自动容量学习或独立显示状态。
- 没有有效当前格式的 Flash 快照时，从 60% 初始化；不自动通过静置 OCV 强制调整。

## 三、满充 100%

- 满充电压使用 `OtherElement.u16Soc_V_100`（LiFePO4 编译默认 3550 mV），要求全部单体采样可信、最低单体高于实际 AFE UV、**此前曾测到 >=100mA 充电电流**、最高单体到达阈值并持续确认约 10 秒。
- 不依赖某个固定尾电流，也不要求此刻电流持续流动；但高压静置且没有本次充电证据时不自动上调。
- 真正确认后，在电流不为负的有效 RUN 周期内以**最多每秒 1 个百分点**增加内部容量，目标锁存到精确 100%。充电器停止、尾流归零和电压放松不撤销已确认目标。真实放电 >=100mA、手动命令、参数变更等会取消待完成目标。
- 如果校准还没结束就进休眠/重启，已提交的满充目标由 Flash 恢复；不使用睡眠时间追赶校准额度。RUN 空闲策略在 AFE 数据可信且目标未完成时，优先允许收敛。
- 此方案不允许满充瞬间跳变。因此对于完全没有充电证据、确认不足 10 秒或刚确认就开始放电的特殊充电器，无法保证在断开瞬间显示 100%。需要实板确认充电器结束特征，不能把高压直接当作实际化学满充的证据。

## 四、放空 0% 和断线隔离

- `OtherElement.u16Soc_V_0`（LiFePO4 默认 3050 mV）是放电末端开始纠偏的电压参考；实际 AFE 参数 `u16VcellUvp`（默认 3000 mV）是末端目标 0 的参照。低压校准需要有效放电与连续约 10 秒低压确认，向下额外修正最多 1%/10 秒；保存进入低压区的单一参考容量，避免反复进出窗口重复扣除。
- **可信 UV 是唯一允许的自动 SOC 跳变**：AFE 已报告 UV，且本轮电压帧完整有效、PF 未置位、实际最小单体与 AFE UV 阈值相容（容差 20 mV），才把剩余容量直接设为精确 0、清余数与目标，并在现有 DEEP/复位路径中尝试写 Flash。
- 如果 UV 已报告而单体数据无效、疑似断线、PF 置位或尚无本轮可信数据：仍立即执行原保护/DEEP，但不乱清 SOC。后续同一 UV 的新有效样本允许再次确认归零，保护事件本身不重复请求。
- RUN 与 RTC 路径共用 `SleepDeal_UpdateOverdischarge(active, voltage_fresh)`；RTC 不能仅凭状态寄存器/旧缓存强制清零。保护不会等待 SOC 估算、断线重试或 Flash 成功而延迟。
- 如果当前硬件没有独立可信的断线证据，所有物理断线形态不可能由软件百分之百识别。确认异常时应保守保留 SOC，而不是把断线误清为 0。

## 五、手动设置与 Flash

- 上位机 `0x1005` 接受 0～100，**立即**把内部精确容量改为相应百分比，这是第二种允许的 SOC 跳变；先成功持久化快照才 ACK，否则回退 RAM 并返回错误。手动修改不增加循环次数，不再保存待完成的手动平滑目标。
- 原有 SOC V2 40 字节快照、68 字节共享状态记录、双页地址/CRC/提交标记/掉电保护均不变；旧手动目标字段写 `0xFFFF`。已提交的完整循环代次不变。旧 UV 零目标不再作为重启后自动归零的证据。
- 日常整数 SOC 或整次循环变更在两次正常保存之间至少间隔 10 秒；关键校准标志变更、手动命令及 NORMAL/DEEP 休眠保存不受该正常间隔限制；失败最多每秒重试一次。
- 当前升级参数配置 `PROJECT_CFG_STORAGE_UPDATE_GENERATION=0`、`MASK=0` 表示默认保留有效快照和参数，不能在普通升级时改变 bit6 或整片擦除。
