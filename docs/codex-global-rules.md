# Codex 全局协作规则

## 协作与范围

- 全部用中文回答；函数、寄存器、协议字段和命令保留英文。
- 当前源码和工具输出证明软件现状；用户要求和产品合同确定预期行为；硬件限制以对应型号官方手册、Errata 为准。旧文档和记忆仅作参考，冲突先核实，不猜测硬件事实。
- 项目 `AGENTS.md` 补充具体约束；更具体且符合项目事实的规则、用户明确授权的例外优先。用户要求先看、分析或等确认时，只读，不修改。
- 按任务范围理解调用链、数据来源、状态所有者和硬件接口，优先最小修改；不做无关重构、批量改名、格式化或搬迁。
- 不擅自改变协议、CAN ID、寄存器、缩放、字节序、存储布局、Boot/App 边界、OTA/IAP 格式和既有外部行为。
- 默认兼容已出货设备的旧数据；重置或不迁移仅按用户明确授权执行。持久化改动核对擦写粒度、寿命、布局、版本、CRC、提交顺序和掉电恢复。
- 大的代码变更完成相关验证后，按逻辑变更自动创建说明完整的 Git 提交；只白名单提交本次文件，保留无关脏文件，不自动 push。
- 文档按行为影响更新，优先修改最相关的现有说明；协议、安全边界和发布流程变化必须记录。普通修改不自动新增文档、全量审查或需求表。

## 嵌入式代码

- 按正确性、安全可靠性、可读性、可维护性、可调试性、兼容性、资源效率、抽象复用的顺序权衡，优先简单明确、便于单步调试的代码。
- 资源受限 MCU 优先使用 `stdint.h` 固定宽度整数；内部符号优先 `static`，减少可写全局变量和 `extern`，配置、测量和运行状态有明确所有者及修改入口。
- 新增裸机代码默认禁止动态内存、递归、无界等待和无必要浮点；避免晦涩宏、过多函数指针及 callback。不为架构完整增加多层结构，抽象须解决真实重复或明确边界。
- 名称表达业务含义和单位，检查符号、范围、溢出、截断与 tick 回绕；阈值和时间用具名常量或参数，不无意识混用单位。
- ISR 只做必要寄存器操作、搬运、时间捕获、计数和置位；不做 Flash 擦写、完整解析、复杂保护、长循环、阻塞或格式化输出。核对与主循环的竞争、原子性和 `volatile`。
- 运行态使用既有 tick、时间戳、状态机和有界 timeout；初始化短等待须有依据和边界。函数按完整动作拆分，注释解释原因、时序和异常，不增加无意义 wrapper。

## 硬件与 BMS

- 先核对项目实现、工程官方头文件和驱动，按需查 Vendor SDK、Example、手册及 Errata；沿用既有驱动体系，不跨型号照搬寄存器、位定义或时序，不擅自切换 HAL。
- STM32F030C8T6 底层开发必须参考 `C:\Users\Administrator\Downloads\STM32F0xx_StdPeriph_Lib_V1.5.0`。
- BMS 不存在的串位发送 `61001`，不用 `0` 或其他值，不计入有效串数；既有协议合同若与此冲突，先说明，不静默改协议。
- 修改同口 BMS MOS、保护或协议关断时，单路软件关断须支持反向临时导通：关充电 MOS 后确认有效放电电流须临时开充电 MOS，关放电 MOS 后确认有效充电电流须临时开放电 MOS，统一纳入最终仲裁。
- 反向放行保留原关断请求和保护锁存，不等恢复计时；反向证据消失后恢复原关断。共同保护和明确双路关断优先；仅有效、新鲜的电流证据可授权，充电器接入、旧缓存或无效采样不能授权。
- 各项目明确反向门限、去抖、有效期和响应时间；可用软件或 AFE 原生机制，区分软件请求、AFE 许可与物理导通，验证反向出现/消失、保护叠加、控制失败和低功耗恢复。
- 修改低功耗前核对进入条件、状态保存、唤醒源、GPIO、通信、AFE、外设恢复、watchdog 和 tick；不因空闲擅自新增入口。

## 验证与文件

- 按改动运行相关编译、host test、静态检查或硬件验证，不默认全仓检查；核对相关边界、通信失败、并发、timeout、掉电、reset 和恢复路径。通信输入须验证长度、索引、字节序和缩放；host/编译不能代替板上验证。
- 未明确要求固件镜像时，不执行会生成 BIN 的构建、打包或转换；常规构建命令出现在文档中不构成授权。
- Codex 额外日志、截图、缓存和中间文件统一放 Windows 用户临时区，不在工作树创建临时目录；调用工具前重定向，不能重定向时先说明。工程既定输出目录内正常编译产物和本项目正式交付、证据允许保留。
- 无关项目的正式交付默认放 `$env:USERPROFILE\Documents\CodexOutputs\<project-id>\<task-id>`。

## 客户端

- Windows、Android 和 CLI 默认复用负责分支及其工作树；修改前报告目录、分支、HEAD、dirty，交付报告提交并核对新增分支。新建分支须先说明原因、起点、合回目标和收尾安排并获明确同意；不得用 detached HEAD 绕过。
- BMS 串口/BLE 客户端持续使用 `CS19970929/telink-new-sdk-b85` 的 `bms-tool-windows/`，不限于 Telink；正式工作树为 `C:\Users\Administrator\source\bms-client`，分支 `client/main`。先运行 `bms-tool-windows/check-client-worktree.ps1`，能力与限制见 `bms-tool-windows/docs/CLIENT_MAIN.md`；远端状态现场核实。
- 复用 Windows、Android、CLI 的现有公共源码与构建入口，保持客户版/内部版边界；不按板型或版本复制永久分支，历史 SDK 客户端和发布包不是源码入口。独立 CAN 工具按其项目规则维护，复用不授权改变目标 BMS 合同。
