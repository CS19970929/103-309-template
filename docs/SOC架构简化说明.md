# SOC 架构简化说明

## 目标

本次调整把 SOC 模块收敛为稳定的运行估算模块，去掉尚未验证充分、会增加状态复杂度的容量学习和动态 SOH 逻辑。保留影响稳定性的核心路径：

1. 200ms 安时积分。
2. 可信满电确认。
3. 静置和 RTC 休眠后的 OCV 小步补偿。
4. 轻载在线 OCV 小步修正。
5. 低压弱单体保护下修。
6. Flash 快照恢复 SOC、放电累计和循环次数。

## 代码边界

`SOC.c` 继续只负责加载配置和 200ms 调度，不承载算法细节。

`SocEnhance.c` 现在只维护必要运行状态：

- 工厂容量 `u32CapFactory`
- 当前容量 `u32CapNow`
- 未满 1% 的积分余量
- 当前 SOC
- 放电百分比累计和循环次数
- 显示平滑、静置、在线 OCV、满电确认等非持久运行上下文

`SocEnhance.h` 删除未实际使用的循环寿命限制字段和调试复用字段，SOH 对外仍保留但固定为 100，容量满充值固定等于工厂容量。

## 持久化策略

Flash SOC 快照仍使用原有 `STORAGE_FLASH_SOC_DATA` 结构，避免破坏后 64K 存储格式和兼容读取。算法层只使用其中的：

- `u16SocNow`
- `u16DsgSocInt`
- `u32CycleTimes`
- `u32CapNow`

读取快照后，若 `u32CapNow` 超出当前出厂容量边界，则按当前配置容量和 SOC 重新计算，避免历史容量学习值或旧配置容量影响当前运行。

## 暂不保留的逻辑

已从算法层移除：

- 满/空锚点容量学习状态机
- 学习后的满充容量 `CapFull`
- `MaxErrorPercent` 置信度字段参与判断
- 动态 SOH 计算
- 未使用的 `u16_SOC_CycleT_Limit`
- 调试复用输出 `u8_SOC_OCV_Cali`

Flash 结构中的旧字段暂不改名、不缩短，作为兼容预留字段保留。

## 预期行为

1. 首次启动或快照无效时仍默认 60% SOC。
2. 充电积分最高先到 99%，达到满电确认条件后才进入 100%。
3. 放电到容量底或低压保护边界时仍能下修至 0%。
4. SOH 上报固定 100，`CapacityFull` 和 `CapacityFactory` 一致。
5. 升级或参数变化后不会再恢复历史学习容量，SOC 容量基准只来自当前 `OtherElement.u16Soc_Ah`。

## 验证

已执行 `FD_Release` Keil 编译：

- Code: `55468`
- RO-data: `3408`
- RW-data: `1292`
- ZI-data: `5756`
- 结果：`0 Error(s), 2 Warning(s)`

两个 warning 为既有的不可达代码提示，位于 `SocEnhance.c` 的故障屏蔽配置分支。
