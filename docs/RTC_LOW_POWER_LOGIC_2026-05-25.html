RTC 低功耗逻辑梳理

适用工程：103 + 309 / STM32F103 / SH367309；日期：2026-05-25

结论

状态源收敛

g_stLowPowerRtcStatus 是低功耗请求的唯一状态源，mode 表示请求模式，readyToSleep 表示已经通过入口判断、准备执行休眠。

诊断字段独立

rtcWake、delaySeconds、delayTargetSeconds、elapsedSeconds 只作为运行诊断字段刷新，不再镜像另一个运行态结构。

STOP 唤醒源

周期唤醒继续使用 RTC_IT_ALR + EXTI_Line17 + RTCAlarm_IRQn，运行态秒中断进入 STOP 前关闭，醒来恢复运行态中断。

主流程

1. 运行态入口

App_LowPowerProcess() 每轮调用 rtc_sleep()。只有 1s 标志到达时执行低功耗判断。

2. 条件判断

BQ769x0_SleepMode_Ctrl() 先处理低压强制深睡，再检查 MCU 唤醒、老化、外部通信、电流和 AFE 状态。

3. 请求落地

满足 RTC 空闲条件后设置 mode = HICCUP_MODE；满足正常/深睡请求后设置对应 mode。

4. 执行休眠

readyToSleep = 1 后按 mode 进入 RTC STOP 周期或写 BootFlag 后复位休眠。

RTC STOP 周期

阶段 函数 关键动作
准备进入 STOP rtc_sleep_prepare_rtc() 保存 CAN/SOC/老化状态，初始化 RTC，切 IO 到 RTC 低功耗状态，设置下一次 RTC Alarm。
配置唤醒 RTC_WKTimeConfig() 关闭秒中断和旧 Alarm，清 RTC_FLAG_ALR 与 EXTI17，按 CAN 空闲策略设置 1s/10s Alarm。
进入 STOP Sys_StopMode() 停 TIM3，清 GPIO EXTI pending，执行 PWR_EnterSTOPMode()，醒来后恢复系统时钟。
RTC 唤醒服务 rtc_sleep_run_hiccup_cycle() 累计 RTC 休眠秒数，更新 SOC 休眠补偿，调用 Can_RtcWakeService() 执行 CAN 探测/发送。
退出低功耗 isException() / report_wkup_sig() 检测电流、AFE 故障、低压和外部唤醒；异常或按键/充电唤醒后退出 RTC 周期并恢复运行态。

阻塞优先级

优先级 条件 处理
最高 单体低于 2800mV 且充电电流不超过 5mA 累计 60s 后请求 DEEP_MODE，不被普通 RTC 延时阻塞。
高 单体低于 OtherElement.u16Sleep_Vlow 按配置低压休眠时间累计后请求 DEEP_MODE。
中 MCU 唤醒脚、工厂老化、外部通信、充放电电流、AFE 非空闲 刷新 blockReason 并清 RTC 进入倒计时，防止误进 STOP。
低 无阻塞且达到 sys_time.time_enter_rtc 请求 HICCUP_MODE，进入 RTC STOP 周期唤醒。

变量职责

变量 职责 说明
g_stLowPowerRtcStatus.mode 当前请求的休眠模式 唯一控制源取代旧 s_stLowPowerRuntime.mode 与 u8SleepModeSelect 双写。
g_stLowPowerRtcStatus.readyToSleep 休眠请求是否已准备执行 唯一控制源取代旧 s_stLowPowerRuntime.armed 与 u8StateSleep 双写；命名含义是“准备执行休眠”。
g_stLowPowerRtcStatus.blockReason 最近一次阻止 RTC 的原因 用于现场诊断，如电流、MCU 唤醒、老化、通信、AFE 非空闲。
g_stLowPowerRtcStatus.rtcWake 最近一次 STOP 是否由 RTC Alarm 唤醒 由 is_rtc_wakekup 派生，便于调试观察。
g_stLowPowerRtcStatus.delaySeconds 当前进入 RTC 的空闲累计秒数 来自 sys_time.enter_rtc_delay。
g_stLowPowerRtcStatus.delayTargetSeconds 进入 RTC 的目标空闲秒数 来自 sys_time.time_enter_rtc。
g_stLowPowerRtcStatus.elapsedSeconds 本轮 RTC STOP 累计睡眠秒数 用于 SOC 休眠补偿和 CAN RTC 唤醒服务节拍。
