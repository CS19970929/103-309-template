# 软件保护与 ADC

## ADC 与 RTC

- 当前只有 PA1 / ADC1 Channel 1 的 MOS NTC 输入，与旧提交 `886feee` 中实际启用的通道及用户确认的接线一致。重构时曾误按旧 `GPIO_ADC_NMOS` 定义改为 PB1 / Channel 9，已恢复 PA1 并修正引脚定义；不能依据过时注释切换采样通道。新增采样只扩展 `ADC_INPUT` 和 `s_adc_inputs`，每路软件触发单次转换，不使用 TIM2、DMA 或 ADC 中断。
- RUN 主循环先执行 `ADC_Task`，再消费完整的新采样组。启动配置和有界校准结束后等待稳定，丢弃一次真实转换，随后取 8 次转换、去掉最大最小值后平均。每轮采样完成后间隔 100 ms。
- 只有确认 EOC 且未超时的数据才能进入采样组；零值、满量程、NTC 表范围外和非法校准结果只表示采样不可用，不能直接视为 MOS 高温。上报保留最近有效温度，但保护不得拿这个缓存推进确认时间。
- `DataLoad_MosTemperature` 是 MOS NTC 查表、原有 K/B 校准和上报编码的唯一入口，保持 `(摄氏度 + 40) * 10` 编码和原校准含义。
- 进入 STOP 时停止 ADC、清除未完成组和待消费样本。RTC 周期检查只读取 AFE 温度。只有真正恢复 RUN，完成时钟、GPIO、通信和系统计时恢复后，才重新初始化 ADC；禁止在 RTC 检查阶段采样 MOS。

## 保护状态与 MOS 许可

- `Fault.c` 负责软件保护状态。每项保护只修改自己的锁存和计时；`Fault_ApplyMosPermits` 集中合并禁用条件。AFE 的方向性保护沿用原有反向电流恢复规则，共同保护独立合并，不能被反向恢复覆盖。
- 软件过流沿用一级电流门限立即触发。30 s 恢复只累计相邻有效电流读数间的实际时间，反向电流暂停累计；通信失败、STOP 和 AFE 重置不累计离线时间，也不清除已确认故障。同一 tick 的任务补跑不能加速恢复。
- 过流故障记录只在未保护到保护的边沿写入，持续超限不会刷满 RAM 故障环。
- `SH367309_SetMosPermits` 合并 CHG/DSG 写入，先读取 CONF，再按需要修改并回读确认。物理 MOS 输出状态只用于上报，不用作跳过许可写入的依据。失败不更新影子值，下一轮重新读硬件并重试；没有新增“已应用”缓存。
- 上电、AFE 重置等实际入口也经过相同保护合并。AFE 参数等待应用或失败时允许维持原有许可、收紧许可，禁止新增许可；配置成功并确认许可后才恢复已有 CTL 放行流程。ADC 未就绪不构成关闭或拒绝放行的条件。

## MOS 过温

- 使用既有 `PRT_E2ROMParas.u16TmosOTp_Third/Rcv/Filter` 和三级故障位 `b1TmosOtp`，同时禁止充、放电。默认 95℃ 连续有效采样确认 1 s 后触发；80℃ 及以下连续确认 1 s 后恢复。触发时沿用既有 `MosOTp_Third` 故障编号。一级、二级 MOS 参数保留，暂不增加新报警行为。
- 只有新的完整采样组能启动或推进确认；首个满足条件的样本只开始计时。无效数据、采样间隔超过 300 ms、STOP、AFE 重置和参数更新均重置未完成的温度确认，不能清除已锁存过温。已锁存状态只能由有效降温样本确认恢复。
- ADC 以 `NONE/READY/INVALID` 区分没有新数据、完整新数据和本次失败，避免把缓存上报温度用于保护计时。ADC 故障诊断本身不关闭 MOS。
- MOS 参数仍占用原有 `0x2132` 起的 5 个寄存器，温度编码与 Flash 格式不变。涉及该参数块的写入在落盘前验证：三级触发值在 0～105℃，恢复值至少 0℃且低于触发值，延时在 1～50000 个 10 ms 内；失败回滚。
- NTC 表范围为 -30～105℃。历史参数若不满足上述组合要求，保护计算临时使用已有出厂值 95℃/80℃/1 s；读回和历史 Flash 数据保持原样，不重置其他参数。有效参数更新只重新开始确认，不释放锁存。

## AFE 参数换算与低功耗命令

- 放电 OCD1T 使用 `u16IdsgOcp_Filter_Second`，充电 OCCT 使用 `u16IchgOcp_Filter_Second`。当前放电设置为 50 个 10 ms，按既有向上取档规则得到 600 ms；修正前误用了充电设置，得到 100 ms。OCD2 固定配置保持原样。
- 档位选择使用 32 位输入，避免延时乘 10 后被截成 16 位，导致大延时反而选到最短档位。超过硬件表最大值仍沿用最大档位，参数读回格式保持原样。
- AFE 参数写入先检查数量、字节数、单项范围和 8 个温度参数的 NTC 表索引，合法后才保存；保存失败回滚。应用配置时再次校验，TR 读取失败或采样电阻换算为零时禁止继续编程。历史存储不因新增检查被整块重置。
- Sleep 命令读取实际 CONF 后只设置睡眠位，不重放旧的 MOS 许可影子；无调用的 IDLE/SHIP 和旧短路参数入口已移除。该清理不改变实际 AFE 配置路径的短路参数。

## 验证边界

`python tools/test_protection_refactor.py` 执行真实 C 源码的 host 回归，硬件接口使用 stub。`python tools/check_bms_no_bin.py --target FD_Release`（或 `FD_Debug`）在用户临时目录编译、链接，关闭用户构建钩子与 HEX 输出，不生成 BIN/HEX，不烧录。

host 和编译结果不代表板上验收。仍需用实际 NTC、供电和示波器确认冷启动与 STOP/RUN 恢复的采样稳定性，以及温度触发、恢复和物理 MOS 动作。

`__SOC_5_PROTECT_` 及其低 SOC 关断/休眠分支已删除。AFE 过放、参数低压定时、MOS 过温、软件过流及反向临时导通条件保留。`Monitor_TempBreak()` 与加热源文件按用户指定保留；加热源文件仍未加入主工程两个有效目标，本次不启用它。
