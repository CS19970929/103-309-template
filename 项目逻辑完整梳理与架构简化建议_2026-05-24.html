1. 运行入口与调度链路

main()
  -> AppInit_Boot()
     -> AppInit_InitDevice()
     -> AppInit_InitRuntimeState()
     -> Init_RTC()
  -> while (1) Runtime_RunOnce()

Runtime_RunOnce() 的正常路径先锁存系统 tick flag，再运行出厂老化、LedBar、AFE/SOC、SCI、ADC、低功耗、CAN、Flash、日志、ProID 和 watchdog。App_SOC() 在 Runtime.c 中被注释，实际从 App_AFEGet() 的 200ms 链路调用。

System_Init.c 的 TIM3 是 10ms 基准，200ms 任务使用 pending period 计数，最多累计 5 个周期。这个设计比单 bit flag 稳一些，主循环短暂延迟后能追赶 AFE/SOC。

3. AFE 与 200ms SOC 链路

App_AFEGet()
  -> MonitorAFE(0, UpdateVoltageFromBqMaximo())
  -> DataLoad_CellVolt()
  -> DataLoad_CellVoltMaxMinFind()
  -> DataLoad_Temperature()
  -> DataLoad_Current()
  -> g_u32AfeCurrentSampleSeq++
  -> App_SH367309()
  -> new_todo_logi()
  -> App_SOC()

UpdateVoltageFromBqMaximo() 从 AFE MTP buffer 读取 cell voltage、NTC 温度和 CADC 电流。DataLoad_Current() 再处理符号、零点和 mA 换算，发布 u16Ichg/u16IDischg。

主要结构问题是 new_todo_logi() 仍在数据处理文件中承担 charger/key/MOS/UL fuse/深度休眠策略。建议第一步只移动并改名，不改变逻辑。

4. ADC 模块与新增一路采样

当前 ADC 是 ADC1 + DMA1_Channel1 + TIM2_CC2 外部触发 + circular DMA，硬件采样 3 路。

DMA rankGPIOADC channel当前语义处理函数
1PB1ADC_Channel_9MOS NTCADC_TTC()
2PA2ADC_Channel_2Type-C 输出分流电流ADC_Current_Smooth()
3PA1ADC_Channel_1总压分压ADC_Vbc()

新增一路采样的最小改动：确认引脚无冲突，将 AD_Used_amount 改为 4，初始化新增 GPIO 为模拟输入，增加 rank 4，同步 ADC_NbrOfChannel，为 raw index 3 增加处理函数，并验证 4 路 DMA 顺序。

中期建议将 raw DMA rank 和处理后的派生信号拆成两个 enum，并建立 ADC channel descriptor 表，避免后续新增采样时改漏。

5. SOC 模块

SOC.c 是适配层，SocEnhance.c 是算法层。适配层负责配置、取样、Type-C 等效电流、通信命令和发布；算法层负责容量状态、安时积分、满充/空端锚点、静置 OCV、小步校准、RTC 补偿、快照和显示平滑。

  • PROJECT_CFG_SOC_CALIBRATION_STEP_PERCENT=1，单次校准最大 1%。
  • PROJECT_CFG_SOC_RUNTIME_TABLE_ENABLE=0，运行时 SOC OCV 表写入关闭。
  • PROJECT_CFG_SOC_BOARD_SELF_CONSUMPTION_MA=30，积分和 RTC 补偿考虑板端自耗。
  • sag/rebound holdoff 避免大电流压降期间误校准。
  • 静置 OCV deferred target 当前只接受向下校准目标，避免回弹抬 SOC。

建议不要立即重写 SOC 算法。可以先按功能拆文件，但保持 SOC_IntEnhance_* API 和测试行为不变。

6. CAN 模块

Can_HDX.c 包含初始化、TX 队列、mailbox 管理、bus-off 监控、周期帧调度、CAN app 命令和 RTC 低功耗发送服务。1000ms 帧发送电压/电流/SOC，5000ms 帧发送容量/SOH/版本/状态/出厂时间。

低功耗路径 Can_RtcWakeService() 打开 CAN 电源，排 1000ms 帧，最多 1500ms 服务 TX/RX/bus-off，然后返回休眠流程。

风险点：放电电流 signed 表达式不够清晰，版本帧硬编码，硬件滤波接受全部帧，app 命令只有一个 pending 槽，状态帧故障优先级是隐式覆盖。

7. LED / LedBar 模块

LedBar 是 5 GPIO Charlieplexing 扫描方案。LedBarRuntime 保存显示状态，TIM4 默认 0.5ms 扫描 tick，APP_LedBar() 处理 MCU_WK、按键、休眠、开机窗口、测试显示和 SOC 显示窗口。

疑点：charge/discharge/fault 有空分支；LEDBAR_ICON_CHARGE_MASK 由 discharge_mos_open 点亮；长按依赖文件级 key_release_wakeup；LedBar_Scan1ms() 名称和 0.5ms tick 不一致。

建议收敛为三层：输入采集、显示模型、扫描输出。

8. 低功耗、RTC 与状态恢复

App_LowPowerProcess()
  -> rtc_sleep()
  -> BQ769x0_SleepMode_Ctrl()
  -> rtc_sleep_prepare_rtc()
  -> STOP
  -> restore after stop
  -> update_rtc_soc()
  -> Can_RtcWakeService()
  -> 若无异常则继续 STOP

SleepDeal.c 管理深度休眠/复位式启动标志和长按休眠，rtc_sleep.c 管理 RTC STOP、SOC RTC 补偿和 CAN 低功耗补发。建议中期增加统一 LowPowerDecision 和 facade API。

9. 存储、通信与参数

  • IAP/Bootloader 地址：0x08000000。
  • App 地址：0x08004800。
  • 后 64K 持久化区从 0x0801C000 开始。
  • CAN app 命令复用 Sci_HostReadWords() 和 Sci_HostWriteWords()。
  • PROJECT_CFG_HOST_WRITE_ENABLE=1，写入仍按地址和范围校验。

StorageFlash_CalcCrc() 当前 payload 小于 255 字节，因此不是现时 bug；但 CRC 长度参数为 8 位，未来大 payload 需要扩展或加保护。

11. 架构简化建议

可以马上做且不影响功能

  • 为 ADC 增加 channel descriptor 表，先覆盖现有 3 路，再接新增一路。
  • 为 CAN app 命令增加 rx_drop_busy、crc_error、cmd_unsupported、tx_timeout 统计。
  • LedBar 清理空分支，确认 icon 语义，将 key_release_wakeup 并入 runtime。
  • 将 new_todo_logi() 移出 DataDeal.c 并改名为 power policy service。

中期重构

  • SOC 按 integrator、OCV、anchor、snapshot、display 拆文件，但保持 API 不变。
  • 低功耗增加 facade，集中输出阻断原因和下一步模式。
  • g_stCellInfoReport 字段 owner 文档化。
  • CAN frame packer、tx scheduler、app command 分层。

现在不建议做

  • 不建议立即推倒重写 SOC 算法。
  • 不建议一次性封装所有全局变量。
  • 不建议新增 ADC 一路时顺手重构所有 ADC 业务。
